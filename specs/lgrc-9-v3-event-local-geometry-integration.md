# LGRC9V3 Event-Local Geometry Integration Specification

**Specification ID:** `lgrc9v3_event_local_geometry_integration_v0`
**Phase 8 tranche:** `Phase-8-LGRC9-EventLocalGeometryIntegration`
**Date:** 2026-08-16
**Status:** Retained prospective requirements; Iteration 96 closed without runtime change
**Graph RC evidence baseline:** `main@47a8a096e86a33b36466bee92738c52bf966ec50`

## 1. Purpose

This specification defines the conditional Phase 8 extension target through
which a committed LGRC9V3 causal event may alter the causally available GRC9V3
geometry/current that determines later LGRC9V3 causal work.

The target relation is:

```text
committed LGRC event
  -> causally available active graph state
  -> geometry/current proposal
  -> bounded current realization
  -> LGRC packet work
  -> later committed event
```

The intended closure is not another experiment-authored route table, score,
winner, or semantic role. It is a default-off runtime relation in which
instance-specific continuation is derived from formed graph state under a
generic LGRC/GRC constitutive contract.

This document is self-contained. It records the theoretical and experimental
lineage, the exact current runtime boundary, the evidence supplied by Gates A
and B, the C0/C1 pre-implementation gate, the proposed native contracts, the
implementation and claim boundaries, and the unresolved decisions that must be
closed before source modification.

It does **not** authorize source changes. Iteration 96 closed the current gate
at the registered C1 action-scope boundary. Any future source-changing Phase 8
attempt would require a new, prospectively governed evidence tranche that
supports all of the following:

1. the external evidence package is locally admitted or reproduced;
2. C0 and C1 are prospectively registered and executed against current source;
3. the C1 gate supports an order/timing effect beyond the C0 full-drain null;
4. same-frontier, causal-availability, integration-interval, and in-flight-state
   policies are selected and frozen in the local repository;
5. the baseline freeze is activated on a clean current Graph RC revision.

## 2. Why This Extension Exists

### 2.1 The wider post-N31 evidence field

The graph program already contains bounded evidence for most neighboring
capabilities:

| Evidence line | Retained result relevant here | Boundary retained |
| --- | --- | --- |
| N22 / SU5 | producer-mediated durable conductance geometry | no native route-conductance memory or native read-back |
| N23 / LC6 | same-run live continuation candidates, collapse records, and selection geometry | selection execution remains bounded and does not establish a continuation spectrum |
| N24 / AB5 | surplus-supported optional continuations and joint admissibility | no history-shaped deformation of optionality |
| N25 / N25.2 | scoped native sub-basin and multi-basin formation | no unscoped ecology or agentic claim |
| N26 | local proxy can improve while basin persistence stalls or collapses | requires independent anti-proxy evidence |
| N27 | bounded transfer under explicit mappings and signature floors | does not establish semantic identity |
| N28 | focal persistence can be generative, extractive, competitive, or neutral for surrounding capacity | no native event-local closure |
| N29 | producer-assisted recurrence, susceptibility/re-entry, and changed-medium feedback compositions | native cross-component composition remains blocked |
| N30 | a non-private medium trace can condition later eligibility | no recurrent read/write cultivation |
| N31 + P2-I3 B-R | complete present causal state can carry a later ecological aftereffect | producer-mediated lifecycle and no inherited downstream evidence |
| N31 + P2-I3 C.2 | a quantity-sensitive functional of qualifying history can alter later susceptibility and can receive one bounded feedback step | qualifying relation and constitutive insertion remain externally authored |

The missing relation is not retention, optionality, basin formation, recurrence,
or history-conditioned effect in isolation. It is the native causal composition
among capacities already present separately.

### 2.2 Core-theory pressure

The current core papers distinguish:

```text
retention
!= active read-back
!= structural write-back
```

and keep the primitive RC state at `(C, J_C)`. The reduced continuation
operator does not settle the active recurrent `(C, J_C)` case. The graph
extension therefore must preserve current, geometry, timing, and causal
ownership rather than introducing a generic memory scalar or route reward.

This specification does not claim to implement the full core Read-Back
operator or the continuum Continuation Spectrum. It defines one graph-native
causalization problem created by those results.

## 3. Gate A and Gate B Evidence

The external probe packages bundled with this preparation archive were executed
against Graph RC `main@47a8a096e86a33b36466bee92738c52bf966ec50`. They are not local Graph RC evidence
until the repository admits or reproduces them.

### 3.1 Gate A — LGRC-to-GRC synchronous-limit readout

Gate A closed:

```text
bounded_positive_state_mediated_synchronous_limit_readout
```

It established, in one registered three-node fixture, that native LGRC packet
execution can inscribe a present graph state which, under one explicitly
orchestrated synchronous-limit GRC reconstruction, produces a differentiated
native GRC transport and downstream choice readout.

It also established the following boundaries:

- ordinary `LGRC9V3.step()` does not automatically rebuild GRC transport,
  identity, or choice surfaces;
- raw packet/event histories with the same declared transport-causal state
  produced the same readout in the registered fixture;
- coherence alone was not the complete causal state: prior flux and retained
  conductance geometry changed later transport;
- payload labels and `basin_id` did not alter transport;
- the GRC reconstruction is an active map whose invocation count changes the
  result and must therefore be frozen.

Gate A supports:

```text
LGRC event inscription
  -> present GRC state
  -> explicit synchronous-limit reconstruction
  -> native GRC transport/choice readout
```

It does not support native LGRC read-back or event-local geometry integration.

### 3.2 Gate B — GRC-to-LGRC synchronous-limit flux packetization

Gate B closed:

```text
B-DOMAIN
bounded_positive_flux_packetization_with_explicit_direct_funding_domain
```

For a frozen native GRC flux snapshot and the registered mapping

\[
p_e = \Delta t\,|J_e|,
\]

with packet direction determined by the flux sign, every directly funded
positive arm produced the same fully drained node-coherence state as one
synchronous GRC continuity update.

Gate B also established a causal-liquidity boundary for the tested direct
packetization procedure:

\[
\Delta t\sum_{e\in\operatorname{out}(i)}J^+_{i\rightarrow e}
\le C_i.
\]

A globally conservative synchronous field may fail this present-funding
condition. The adapter must fail closed rather than clip, rescale, borrow future
arrivals, or partially schedule the field.

Gate B supports:

```text
native GRC flux snapshot
  -> generic sign-and-dt adapter
  -> LGRC packetized causal work
```

inside a fixed-topology, fully drained, directly funded synchronous-limit
domain. The adapter and its invocation remain experiment-owned.

## 4. C0, C1, C2, and C3

These objects must remain distinct.

### C0 — full-drain checkpoint recurrence

C0 composes Gate A and Gate B only after the packet queue has fully drained.
It is the synchronous-limit null model and co-simulation control.

A positive C0 result means repeated bridge composition is consistent with a
bounded operator-split synchronous evolution. It does not establish a new
ecological mechanism or event-local closure.

### C1 — event-triggered global interleaving probe

C1 invokes a global GRC reconstruction after a committed event and before full
queue drainage, then permits only the trigger node's derived outward current to
become packet work. C1 remains globally informed and producer-mediated.

C1 exists to determine whether event ordering can become consequential through
the geometry/current bridge and whether the remaining hidden mechanism is the
external global orchestrator.

Only a bounded `C1-ORDER` result surviving the registered controls can open the
C2 source-change gate.

### C2 — native event-local or causal-frontier integration

C2 is the conditional Phase 8 target defined by this specification. It moves
trigger, causal-state selection, geometry/current proposal, current lifecycle,
packet transduction, and recurrence ownership into explicit default-off LGRC9V3
runtime contracts.

### C3 — confirmation-coupled structural cultivation

C3 would interpret later consequences as maintenance, weakening, release,
redirection, or transformation of the retained relation. C3 is downstream
scientific work and is out of scope for the first C2 implementation tranche.

## Scientific Function and Downstream Utility

The extension is not justified merely because it forms a new software loop.
Its scientific function is to make **causal timing participate in formation**.
A committed local event should be able to alter the geometry/current available
to later events before a global full-drain checkpoint erases the path by which
the state formed.

The reusable mechanism is provisionally:

> **Event-local formed susceptibility:** a committed local participation event
> changes the causally available geometry through which the same participant,
> boundary, or medium responds to the next event.

At the runtime level this is more precisely:

```text
event
  -> causally available active state
  -> geometry/current proposal
  -> trigger-owned causal work
  -> later event
```

This is a building block, not a role, agent, ecology, or normative objective.
If later validated, it could be consumed by at least these downstream lines:

### Asynchronous shared-medium co-response

N30 established that a non-private medium change can condition a later
participant. Event-local geometry integration would allow the later
participant's response to alter the medium before still later participants
arrive:

\[
A\rightarrow M_1\rightarrow B\rightarrow M_2\rightarrow C.
\]

The order and timing of participation could become causally relevant without
requiring direct messages or a central route selector.

### Context-sensitive route formation

A route would not strengthen merely because it was traversed. An event would
change local state, native geometry would determine available current, and only
that current would become causal packet work. This supplies a lower-level
mechanism for route capture, release, detour, congestion response, and stale or
false trace rejection.

### Support and capacity circulation

Gate B showed that a globally conservative current is not automatically
present-funded causal work. Event-local integration therefore exposes local
reserve, timing, buffering, and replenishment as real formation constraints.
This is directly relevant to support-conditioned formation and capacity
circulation, but the first tranche remains inside the direct-funding domain.

### Boundary-conditioned exchange

A boundary encounter could change the local geometry that conditions subsequent
admission or export. Later arrivals would encounter a changed boundary rather
than a static permission table. The implementation itself does not claim an
ecological boundary regime.

### Role susceptibility and migration

Changed demand or local history could alter which participant/current relation
is presently viable without installing a fixed role label. This can later be
consumed by role-regeneration experiments, but no role claim belongs to Phase
8.

### Lower-stack support for AP4/AP5

The extension could provide source-current evidence that retained consequence
and current context affect present native continuation. A later agentic
mechanism could consume that surface for consequence-sensitive selection or
runtime-derived proxy formation. The extension itself does not establish
semantic choice, intention, or agency.

The utility requirement is deliberate: a Phase 8 extension should travel to
more than one fixture or downstream question. Otherwise it is likely an
experiment adapter rather than substrate development.

## Why This Is Not N30, C.2, or Full-Drain A+B

### N30

N30 supports:

```text
participant activity
  -> non-private medium change
  -> retained trace
  -> changed later eligibility
```

It does not require present-current selectivity, current write-back, repeated
closure, or event-local causal timing. Event-local geometry integration may
later realize a deeper shared-medium relation, but it is not another N30 claim.

### P2-I3 C.2

C.2 already supports a bounded recursive relation:

```text
qualifying history
  -> derived susceptibility
  -> local packet opportunity
  -> native traversal
  -> changed qualifying history
  -> later susceptibility
```

Its qualifying relation, history functional, susceptibility law, temporary
conductance overlay, and opportunity construction remain RCAE/producer-owned.
The Phase 8 target is not to repeat that lifecycle. It is to move the generic
trigger, causal-state, geometry/current, and packet-work relation into LGRC9V3
without installing fixture-specific semantics.

### Gate A + Gate B full-drain recurrence

Repeated Gate A/Gate B composition after full queue drainage is the C0 null:

```text
reconstruct global current
  -> packetize one synchronous continuity interval
  -> drain all packets
  -> reconstruct again
```

This can provide useful co-simulation and consistency evidence. It does not
make causal timing constitutive when intermediate histories that end in the
same declared state are compressed away. C2 requires ordinary event-queue
ownership and no external checkpoint controller on the positive path.

### Event-triggered global C1

C1 is a necessary phenomenon probe because it can reveal an order/timing effect
before full drainage. It remains globally informed and producer-mediated. A
positive C1 result justifies asking whether the external orchestrator should be
naturalized; it does not itself establish local causal geometry.

## Pressure-Derived Distinctions

The following distinctions are part of the specification because the evidence
and source audit showed that collapsing them creates false positives.

### Retention versus active read-back

A state may persist without changing present current. Retention alone is not
the target.

### Raw history versus transport-causal state

Gate A found several distinct packet/event histories with the same registered
transport-causal state and the same GRC readout. The first implementation must
therefore locate exactly which state/history fields are causally consumed. It
must not claim raw-history sensitivity without a matched-state discriminator.

### Runtime visibility versus causal availability

Global state and the future queue may be stored in memory without being
causally available at one local event boundary.

### Read scope versus action scope

Exact proposal construction may read a dependency-closed neighborhood larger
than the trigger node. The first tranche permits only trigger-node-owned
outward packet work.

### Geometry proposal versus committed current

A proposal is a pure derived artifact. Current becomes causal only after timing,
funding, scope, staleness, and exactly-once ownership gates pass.

### Event time, proper time, and integration interval

These are different quantities. Scheduler tie-break order is not automatically
physical time, and a synchronous-limit `dt` is not automatically a native
LGRC integration law.

### Current existence versus temporal ownership

The same reconstructed flux cannot be packetized repeatedly merely because a
later event can still see it. Every realization owns one interval or equivalent
causal-work claim.

### Global conservation versus present funding

Gate B established a directly funded packetization domain. The first tranche
fails closed outside that domain rather than adding hidden credit.

### Mechanism readout versus continuation evidence

Proposal flux, compatibility, packet count, and funding success show that the
mechanism ran. They cannot serve as the sole evidence that later continuation
improved.

### Implementation acceptance versus N32 evidence

Phase 8 may establish a bounded substrate capability. A separate source-current
validation experiment must establish what the implementation supports, and a
later N32 experiment must establish any scientific mechanism that consumes it.

## 5. Existing Runtime Boundary

### 5.1 Synchronous GRC9V3

Synchronous GRC9V3 already provides a native closure of the form:

\[
(C_t,K_t,J_{t-1},\mathcal G_t)
\rightarrow
J_t
\rightarrow
C_{t+1}.
\]

Current conductance depends on coherence, gradient mismatch, and prior flux.
Native choice surfaces are derived downstream of current; they classify current
organization and do not generate it.

### 5.2 Event-driven LGRC9V3

LGRC9V3 composes a GRC9V3 base state with:

- deterministic packet event queue;
- packet ledger and in-flight budget;
- event time and node proper time;
- causal edge delays;
- explicit causal routes;
- local-update and topology-event histories;
- default-off producer and topology contracts.

`LGRC9V3.step()` processes one queued event. It does not call synchronous
`GRC9V3.step()` and does not automatically rebuild transport or choice state.

### 5.3 Current missing composition

The current repository separately contains:

```text
native event inscription
native GRC state-conditioned transport
native LGRC packet execution
native event queue recurrence
```

but lacks the ordinary runtime relation:

```text
committed LGRC event
  -> causally owned geometry/current proposal
  -> geometry-derived LGRC packet work
```

without preconfigured route tables, externally supplied candidate scores,
fixture-specific target labels, or a global checkpoint controller.

## 7. Terms

### Trigger event

A committed runtime event that may open one geometry-integration evaluation.
The first tranche is limited to committed packet arrival after target credit,
proper-time update, and declared local-update completion.

### Causal availability

The subset of runtime state legitimately readable at the trigger boundary. A
value is not causally available merely because it is stored in the model.
Every consumed value must have source identity, temporal freshness, and a
causal or retained-state justification.

### Read scope

The nodes, edges, parameters, prior-current fields, and boundary values read to
construct the proposal.

### Action scope

The nodes and edges authorized to generate new packet work. The first tranche
limits action to outward current owned by the trigger node, even if the read
scope is larger.

### Dependency-closed scope

A read scope containing every endpoint and local relation required by the
chosen exact GRC transport computation, or explicit causal boundary values for
relations outside the scope.

### Geometry/current proposal

A deterministic, serialized, non-budget-mutating artifact derived from one
trigger state. It may contain proposed gradients, conductance, potential,
flux, and downstream choice annotations. It is not committed current and
cannot itself mutate coherence, topology, queue state, or claims.

### Current realization

A prospectively identified use of a proposal current over one non-overlapping
integration interval or equivalent causal-work claim. It owns the packet work
created from that temporal portion of current.

### Integration interval

The amount of current-time represented by one realization. Event time, target
proper time, and integration interval remain separate fields. Their relation
must be policy-defined and serialized.

### Committed current

Current whose temporal ownership and packet transduction have been accepted by
the runtime. A committed current can be consumed, superseded, or invalidated;
it cannot be silently emitted twice.

### Same frontier

Events sharing a declared event-time boundary or another explicit causal
frontier. Scheduler tie-break order alone is not automatically physical time.
A same-frontier policy must be selected before source changes.

```text
event_local_geometry_integration_enabled = false
event_local_geometry_integration_policy = disabled
event_local_geometry_integration_validated = false
event_local_geometry_integration_supported = false
```

Candidate active-policy identifier:

```text
event_arrival_dependency_closed_geometry_v1
```

The exact public names may be changed during the contract-schema iteration, but
all semantics in this section must survive.

Rules:

- enabled requires a non-disabled policy;
- active policy requires enabled;
- validated requires enabled and passed source-current validation;
- supported requires validated plus the Phase 8 closeout boundary;
- disabled mode emits no proposal/current-realization records and schedules no

- existing GRC9V3 and LGRC9V3 behavior remains unchanged when disabled;
- enabled does not imply validated, supported, ecological, or agentic status.

## 9. Trigger and Ordering Contract

### 9.1 Trigger boundary

The first native trigger may occur only after a packet-arrival event has:

1. been selected by the deterministic event queue;
2. credited target coherence;
3. advanced the declared proper-time state;
4. completed the declared arrival-local update;
5. committed its packet/event record.

Pre-arrival or partially committed state cannot open a native proposal.

### 9.2 Same-frontier policy gate

Before implementation, the repository must select and freeze one initial
policy:

```text
batch_same_event_time_v1
```

or

```text
serialized_committed_event_v1
```

If serialized queue order is selected, the claim must remain computationally
serialized and must not be described as a physical simultaneous-event law.
Both policies require a same-frontier control in later validation.

### 9.3 Exactly-once trigger

One committed event/frontier may create at most one proposal per enabled policy
and declared trigger node. Stable idempotency keys must block duplicate
proposals after replay, restore, or repeated producer evaluation.

## 10. Causal Availability and Scope

### 10.1 Runtime visibility is not authority

The event queue, global base state, future arrivals, and cached surfaces are
runtime-visible. The proposal may consume only values permitted by the active
causal-availability policy.

The first tranche must reject:

- future event outcomes;
- state written after the trigger boundary;
- remote values lacking a retained or causal-path justification;
- hidden experiment arrays;
- fixture-authored target identities;
- post-hoc labels or scores.

### 10.2 Read scope and action scope

Read scope and action scope are independently serialized.

The proposal may read a dependency-closed neighborhood larger than the trigger
node. Packet work may be generated only from the trigger node's declared
outward current in the first tranche.

A scope-leak validator must fail any record where packet actuation exceeds the
authorized action scope.

### 10.3 Dependency closure

The implementation must document which state is required by the selected GRC
operator. If an exact local operator needs neighboring endpoint gradients,
potentials, conductance, or prior flux, those dependencies must be included or
represented by explicit causal boundary values.

The implementation may not label a truncated global reconstruction as an exact
local GRC update.

### 12.1 Temporal ownership

Two committed current realizations may not claim overlapping integration
intervals for the same trigger node and policy unless a later specification
explicitly defines lawful decomposition.

The same proposal current over the same interval may not be packetized twice.

### 12.2 Staleness

A proposal is stale when a load-bearing state field in its source-state digest
changes before commitment. Stale proposals must fail closed or be explicitly
superseded; they may not schedule work.

## 13. Time and Integration Policy

The runtime must preserve:

```text
event_time_key
node_proper_time
integration_interval
```

as distinct quantities.

The first source-changing iteration may not begin until one integration policy
is selected and justified. Candidate policies include:

- target proper-time increment;
- event/frontier-time increment;
- another bounded causal interval derived from existing timing state.

A fixed synchronous-limit `dt` remains valid for C0/C1 controls but is not by
itself a native event-local timing law.

Silent clipping, adaptive rescaling to force funding, or borrowing future
arrivals is prohibited.

## 14. Direct Funding and Packet Transduction

For the first tranche, a current realization is eligible only if every
trigger-owned departure is presently funded:

\[
\Delta t_{\mathrm{eff}}
\sum_{e\in\operatorname{out}(i)}J^+_{i\rightarrow e}
\le C_i.
\]

If not, the full realization fails closed before packet scheduling.

The packet mapping is:

\[
p_e=\Delta t_{\mathrm{eff}}|J_e|,
\]

with physical direction determined from the flux sign and edge orientation.

The runtime must not:

- partially schedule a failed realization;
- rescale the current;
- use future incoming packets as present funding;
- create negative coherence;
- apply synchronous continuity in addition to packetized continuity.

Packet IDs and packet events must cite the current realization that authorized
them.

## 15. Event-Queue-Owned Recurrence

If a realization commits and schedules packet work, ordinary LGRC packet events
own debit, in-flight state, arrival, credit, local update, and the next trigger
boundary.

No external checkpoint controller may be required to decide when the next
proposal opens in a supported C2 claim.

The first tranche may remain fixed topology and trigger-node scoped. It must not
silently claim global event-local geometry or topology-changing closure.

## 16. In-Flight State

The implementation must state whether proposal construction consumes:

- node-resident coherence only;
- already committed pending-flux summaries;
- causally available incoming commitments;
- prior committed current;
- another explicit retained surface.

Future event outcomes cannot be read.

The chosen representation must preserve budget accounting, restoration, replay,
and source-state digest identity. If this question cannot be closed without a
new state surface, that surface requires its own contract and tests.

## 17. Budget and Conservation

Every proposal and realization records the node-plus-packet budget context.
Only packet execution mutates the conserved budget.

At every packet transition:

\[
B=\sum_i C_i+\sum_p C_p
\]

must remain within the repository tolerance.

Proposal fields, scores, compatibility annotations, and derived surfaces are not
coherence budgets and must not be merged with the conserved accounting surface.

## Focused checks

[Four test methods](../verification/test_p976_lineage_ownership.py) cover:

1. A_PC positive ordinary step → reset → rebase → A_CI+PC migration → C_PC
   reconstruction → signed/permuted representation → zero-duration step.
   A literal ordered-rank oracle checks every parent and the complete ledger
   partition, including the singleton representation group among four-receipt
   groups. Observation, failed calls and lawful unreceipted assignment preserve
   the ledger/head; the following successful step uses that head, even though
   assignment changed scientific state. Public restoration accepts that history.
2. Ten parent mutations on a shorter generic history: missing, skipped, foreign,
   nonprimary, extra, reordered extra, duplicated parent, intra-commit parent,
   disagreeing auxiliary and forward-but-acyclic parent. Receipt hashes, commit
   hashes and backlinks are recomputed and checked before public restore rejects
   them. The forward case points at an actual later receipt content ID without
   requiring a cyclic hash fixed point. Three additional partition mutations
   duplicate a group, reorder groups or leave the ledger uncovered. Separately,
   actual migration, reconstruction and representation attempts emit coherently
   hashed wrong-parent groups through an injected receipt builder; all reject
   before whole-publication replacement, preserving the exact previous snapshot.
3. A C_PC representation as the first successful operation establishes a
   singleton parentless root. Duplicate and save/load controls preserve it;
   mutating an exported scientific/receipt/commit/archive/registry payload cannot
   modify any owner. Two forks may produce the same content IDs for identical
   continuations. Resetting one and rebasing the other then produces independent
   valid histories without changing the original or loaded owner. Separate locks
   and owned publication objects are checked; immutable value sharing is allowed.
4. Reuse the accepted P9-4.9.2 symbolic validator's nine valid controls and
   sixteen rejected projections, including self, forward and cyclic parents,
   duplicate receipt IDs and group-order defects. Add a valid mixed-arity
   projection. These are explicitly symbolic, with zero runtime executions;
   they are not mislabeled as coherently hashed cyclic receipt histories.

## Boundaries

These finite histories exercise generic parent ownership across ordinary,
reset/rebase, migration, reconstruction and representation operations, not every
profile/graph/parameter combination. P9-7.7 owns per-profile G2 review; P9-7.8
owns the exact G3 support set. Existing accepted C_OS support is unchanged.

Within-ledger uniqueness does not mean globally unique execution IDs across
forks. Content hashes and valid parent structure do not authenticate an
unobserved uninterrupted execution, forbid lawful unreceipted assignment, or
prove the truth of arbitrary supplied scientific history. Self/cyclic symbolic
pressure must not be added to the native execution count.

# P9-9.4a — bounded enabled/disabled crossings

Implemented and tested; pending independent review and user acceptance.
P9-9.3 was accepted and committed as `b894c95d` before this work. This child
connects the enabled owner and exact legacy delegate for **C_OS, C_CI, A_CI,
A_PC**, on explicitly unchanged port graphs. Public construction/discovery is
still P9-9.4b; optional completion/hierarchy, six other families and aggregate
Tranche 9 acceptance remain unselected/open.

## Contract and implementation

[The specialization specification](../../../specs/grc-9-v4-spec.md), especially
§§12.3, 12.5–12.6, and the [receipt interface](../../../specs/grc-common-interface-v4-ext.md)
are the source. [Forensic traces](./P9-9.4a-Authority.json) retain the exact
initializer, disabled-state and disabled-lifecycle parents. Their disposition
remains `specialization_only` / `indeterminate_requires_review`; execution does
not promote it to normative accepted scientific authority.

[`GRC9V4BranchOperation`](../../../src/pygrc/models/grc_9_v4_crossing.py) is an
internal owner. A migration requires a typed direction, operation ID, exact
source lifecycle digest, and complete direction-specific declaration. Changing
profile parameters alone never switches the live branch.

Entry declares native configuration and incoming edge weights/flux separately
for current and reset. It transports each resource vector exactly, reconstructs
native fixed-row differential, conductance, transport and identity stages, and
constructs a fully rebuilt native reset baseline. It archives both V4 authorities
and records candidate/carrier history losses only where those slots existed.
The scientific branch is an exact native snapshot; V4-only observations are
projected away. The final pointer changes only after both roles and receipts
validate. No old GRC9V3 source or specification changes.

Return requires a complete enabled reference on the same port graph/context.
C uses its complete reference map and reconstructs its derived state. A uses
exactly the specialization's history-free native initializer:

$$
W_{A,e}^{init}=\max\{10^{-12},\exp[-\alpha(C_u+C_v)/2
-\beta\lVert g_u(C)-g_v(C)\rVert^2/2-\gamma(J_e^{in})^2/2]\}.
$$

The incoming stage is the actual native weights/flux at return; row gradients
are freshly evaluated from that role's resources. Alpha/beta/gamma come from
the declared target A profile. Current and reset are computed independently.
This is the native fixed-row initializer, not the generic WLS reference pass,
not restoration of the archived W. A_PC starts both target carriers at canonical
zero. The closed enabled constructor reconstructs and readmits both complete
realizations, including their native solver/geometry constraints, before commit.

## Coordinate, identity and replay layout

Native integer node/edge IDs are ordered-coordinate encodings of the retained
V4 graph. The original typed IDs, port assignments and edge kinds remain in the
bound reference. Native endpoint ordering is canonical; a reversed edge also
reverses the incoming signed flux. This is an encoding, not a topology event.
Return rejects missing/extra/altered coordinates rather than inventing lineage.

Disabled scientific/reset identity envelopes bind exact native serialized bytes
(including signed zero), the combined model identity and the retained graph.
They use the receipt identity prefixes but explicitly named disabled-envelope
preimages; they are not passed off as generic V4 authoritative tuples. Entry
receipts belong to the wrapper ledger, outside their own target preimage.

One persistent typed ledger spans both branches. Migration primaries include
channel dispositions, the resource/history map identities, endpoint identities
and the previous successful primary. Legacy reset follows native clock/baseline
semantics while wrapper chronology persists. Enabled reset retains enabled clock
semantics. Charge deltas subtract exact represented resource sums before rounding
the receipt scalar; they do not subtract already rounded totals.

Checkpoint replay starts from the bound enabled seed and executes the declared
journal. It checks final state, receipts, archives, initialization witnesses and
lifecycle identity. Duplicate owners are independent. Unknown fields, duplicate
JSON keys, stale sources and altered retained entries reject. This remains an
internal checkpoint, not a new public snapshot format promise.

## What ran

Four independent family processes ran in parallel with FLINT and explicitly
selected `legacy_exact_v1`. Each has four tests, with no skips:

| Family | Retained execution | Positive continuation | Excluded native timestep |
|---|---|---|---|
| C_OS | [record](./P9-9.4a-C_OS.json) | passes | next enabled step rejects at charge admission |
| C_CI | [record](./P9-9.4a-C_CI.json) | passes | return rejects at target readmission |
| A_CI | [record](./P9-9.4a-A_CI.json) | passes | next enabled step rejects at charge admission |
| A_PC | [record](./P9-9.4a-A_PC.json) | passes | next enabled step rejects at charge admission |

The positive fixture uses declared native and enabled durations `2^-12`, with
nonuniform incoming weights/flux and distinct current/reset authorities. It
executes an enabled prefix, entry, native step, native reset, another native step,
return, enabled positive step and enabled reset. All eight commit groups retain
valid parentage. Native results, snapshots and observations compare exactly with
an independent unchanged GRC9V3 owner. A scalar row/exponent oracle checks native
entry conductance and both A return initializers without calling the production
gradient/initializer functions.

Negative pressure includes a real reset-only malformed entry stage, stale and
malformed requests, changed ports, injected reset-only return admission failure,
and unexpected late publication failures in both directions. Whole snapshots
and publication pointers remain unchanged. Replay tests mutate archives,
receipts and declarations; successful replay and duplicate independence are also
executed. The injected return failure is a transaction test, not a separately
proved reset-only numerical exclusion.

The original native `dt=1/32` continuation depletes a resource after reset. Its
actual behavior remains a negative control; no legacy clipping or scientific
threshold was changed. C_CI cannot readmit that return state. The other three
can reconstruct it but cannot take the requested next enabled positive step.
This exposed a real enabled-owner reporting defect: post-solver resource failure
was labelled `domain_failure` as a solver disposition, causing the result schema
to raise. It now preserves `valid_root` and emits the typed noncommitting failure.

Accepted 9.1b/9.2/9.3 records remain unchanged. The small
[`p994a_owner_successor`](../verification/p994a_owner_successor.py) adapter binds
the exact old/new owner hashes and reads the old owner preimage from the accepted
commit. It authenticates historical 9.1b evidence without relabelling it as a run
of the corrected owner. The new execution records bind and pressure current code.

Additional checks: 14 focused Python integrity/API tests and six browser tests
pass. The current phase boundary passes with 703 protected baseline files and
340 registered runtime files (47.3 seconds). Final documentation/formatting-only
bindings were refreshed separately; no numerical campaign was repeated for them.

## Scope limits and reproduction

This proves the declared same-graph crossing paths, not an arbitrary legacy
configuration or target parameter neighborhood. The internal receiver rejects
legacy steps that alter its coordinate population; it does not guess a return
map after legacy topology growth. P9-9.4b must preserve this explicit domain or
supply and verify additional mapping support before advertising it. The standalone
native delegate's previously accepted behavior is unchanged. Public saturated
expansion rejection still belongs to P9-9.5.

These small crossing fixtures do not erase earlier CI resolution limits, A_PC
pointwise carrier margins or large-graph exclusions. They are numerical
conformance evidence, not new uniform error certificates. API/browser/notebook
queries authenticate retained evidence only; they never rerun native steps or
accept the child. Each retained file is below 1,000,000 bytes; no oversized raw
evidence is introduced.

From the repository root, check retained integrity with:

```sh
PYTHONPATH=src:.:implementation/phase-9-grcv4/verification .venv/bin/python implementation/phase-9-grcv4/verification/p994a_crossings.py --check --family C_OS
```

Substitute C_CI, A_CI or A_PC. To rerun without overwriting evidence:

```sh
PYTHONPATH=src:. .venv/bin/python -m unittest tests.models.test_grc_9_v4_crossing.COSCrossing
```

The other classes are `CCICrossing`, `ACICrossing`, `APCCrossing`; these may run
as independent processes. `--run` emits a new record only when its destination
is absent. Generated records over 1,000,000 bytes use `.json.xz` automatically.

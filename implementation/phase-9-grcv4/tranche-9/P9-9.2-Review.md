## Implementation and boundary

[GRC9V4LegacyDelegate](../../../src/pygrc/models/grc_9_v4_legacy.py) owns a
private instance of the unchanged GRC9V3 implementation. It starts from an
explicit legacy target snapshot, with the exact selected V4 profile and
specialization held separately as execution context. No enabled V4 numerical
kernel, A history, C sector/resolvent state or PC carrier is executed/stored in
the legacy scientific projection. No existing legacy source is modified.

Each transition runs on a private copy and publishes once after validation.
State and observable reads are detached; the state view is recursively
immutable. Snapshots, saved files, observables and native StepResults preserve
the native legacy vocabulary and values. The separate component checkpoint
binds the complete V4 model identity and exact legacy target version. It is
not the final scientific-branch union or public GRC9V4 facade.

The oracle is the independently owned native GRC9V3 target instantiated from
the same declared seed. This is exact implementation compatibility, not an
independent mathematical derivation or numerical error certificate. Full
snapshot serialization is compared, including signed zero. The wrapper uses
native arithmetic, since substituting a different numerical backend would
change the compatibility target.

Native reset rewinds the native clock and restores its original baseline;
rebase replaces that baseline. The current legacy `prune` mode is a no-op.
These behaviors are preserved, not repaired. Development pressure found that
V4's stricter JSON state type rejects a valid legacy `-0.0` on an isolated
node. The legacy view now preserves it exactly; checkpoint/restore and full
serialized equality cover the correction.

The V4-only subclass checks actual native spark candidates at the native
post-flux/identity detection stage. A saturated old boundary has the known
port-5 collision and raises `legacy_expansion_target_undefined` before any
publication. The shared test checks this guard on an explicit spark call and
preserves the entire live snapshot/pointer. It does not exercise an admitted
saturated legacy expansion. P9-9.5 still owns full-wrapper failure receipts and
crossing integration of this boundary.

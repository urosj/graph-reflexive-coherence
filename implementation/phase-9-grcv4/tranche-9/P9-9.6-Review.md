## Three boundaries that matter before stronger publication

### 1. A real mandatory basin-interface gap

The [specialization spec](../../../specs/grc-9-v4-spec.md#capabilities) requires
`basin_attributes`; the enabled public API does not advertise it. Its readable
state also has no `basin_identity` surface, while the specified lifecycle state
includes that field. All four retained public construction records exhibit
the missing capability, and the current source bindings and state fields agree.

The baseline basin-seed predicate already exists in
`GRC9V4CandidateAssessment.basin_seed`. That predicate and the exposed row
gradient/Hessian do **not** by themselves establish the required public basin
identity, observable and lifecycle behavior. Adding a capability string would
not close this gap.

This is **separate from optional completed sparks and hierarchy**. Those remain
unselected and do not block the declared partial scope; they cannot be used to
waive the baseline basin obligation. Record `basin_surface` under P9-10.1:
trace the baseline basin contract, supply its public state/observable and
lifecycle behavior, and test it before a full-conformance claim. If that work
exposes missing scientific authority, resolve that exact contract through the
established authority path instead of inventing a runtime convention.

### 2. The frozen umbrella capability has an all-forty condition

The frozen spec explicitly requires **all 40 profile-by-surface delegate
vectors** before advertising `grc9v3_disabled_compatibility`. The selected
sixteen cells pass, but the other twenty-four have not been executed.
The same section requires this capability for a full-conformance label.

Consequently this review does not grant either that umbrella capability or full
GRC9V4 conformance. It records the real four-family implementation and exact
defined-domain compatibility evidence as **bounded partial support**. It does
not silently reinterpret the frozen capability condition, enable six additional
families, or rewrite accepted history. The `umbrella_compatibility` item routes
the publication limit to P9-10.1; changing the condition or selecting additional
execution would be a separate scope decision.

### 3. Expanded target identities do not inherit source-cell acceptance

Each tested expansion changes the complete profile and combined model identity.
The expanded targets have accepted enabled/public continuation and replay
evidence. The sixteen disabled-component cells, however, name the original
source identities. The reviewed crossings are likewise same-graph source-model
crossings. They do not establish those four disabled surfaces for every expanded
target, large-graph profile, arbitrary parameter variant or registered declaration.

The record therefore marks expanded-target disabled coverage as **not executed
for that exact target identity**. This is a coverage boundary, not evidence of
a failed implementation. `target_identity_scope` under P9-10.1 requires exact
identity-based publication; add only the missing identity-specific checks if
that broader disabled scope is actually selected. Do not rerun the accepted

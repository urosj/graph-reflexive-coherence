## Expansion operands and boundaries

| Operand | Owner and admission rule |
| --- | --- |
| Source graph, current/reset state and identity | Admitted committed lifecycle; saturation and no source self-loop checked before construction. |
| Source-node choice | Request names an eligible source; the detector does not select among all candidates or generate a complete request. |
| Effective capacity | Request supplies an integer, not a Boolean, at least 9; derive `max(4, ceil((D_eff - 2)/7))`. |
| Chirality and phase | Explicit request data: chirality ±1; phase 1–3 iff the extra-node remainder is nonzero, otherwise null. No implicit RNG, ID parity or iteration-order choice. |
| Resource shares | Request supplies a nonnegative simplex triple; map current and reset independently using the same triple. Core and extra nodes receive exactly zero. |
| Target profile template and specialization | Explicit identity-bound request references with available complete preimages; compute the target from those and the canonical allocator, never from a caller target graph. |
| Bond seed | Resolved positive expansion-policy value, bound in event identity; not itself a solved current or a persistent carrier. |
| C references | Template constructs a complete exact stable-edge `W_C_tr` map before selector/Hodge/current rederivation. |
| A history | Explicit candidate policy: admitted old-edge transport/initializer, admitted full-target policy or declared full-target loss; independent current/reset construction. P9-8.3A.1 owns selection and oracle. |
| Persistent history | Separate carrier policy: admitted whole-carrier transport or archive/drop and whole-target zero reset. Never partial preservation with zero-filled new components. |
| Event and role IDs | Derived from canonical preimages after operand validation; expected digests are assertions, not supplied allocation authority. |

Candidate A owns W history; Candidate C does not. Only PC and CI+PC own Z,
independently of candidate. Field `Split` decodes column coarse data; it is
not graph fission. Mechanical expansion is a separate transaction after an
ordinary commit. Its failure preserves that committed source and the entire
pre-event publication, including reset, receipts and identity.

**Confirmed numerical entry issue:** the C_OS construction source uses unit
edge weights and `Lambda_C = 1`. At reference geometry the nine-leaf star
has eigenvalue 1. Independently, a vector with +1 on `outside-1`, −1 on
`outside-4` and zero elsewhere satisfies `L v = v`. Those leaves remain
attached to the same satellite in the D30 target, so the same exact witness
survives its reference reconstruction. The native `CandidateCSelector`
rejects both with `selector cutoff lies on the exact spectrum`.

The [three retained readiness tests](../verification/test_p980_readiness.py)
verify the exact rational witness and native rejection on both graphs. A
cutoff-0.5 source control selects the constant sector, showing the rejection
is not a blanket failure of the primitive. That control is **not** a selected
runtime profile, a full current solve or target readmission. Zero C is legal
authoritative data; do not change the specified zero-resource map to conceal
a spectral or other domain failure.

Keep the frozen allocation/identity vectors unchanged. Before production,
P9-8.3C-OS's oracle work must add a
separately identified native numerical fixture outside the release, with
independent expected current/geometry and distinct current/reset inputs.
Check source and target spectral gaps, SPD/conditioning, resource admission,
charge and actual continuation. Demonstrate candidate detection in P9-8.1c
on a compatible admitted source. The frozen vector's `committed: true` is a
construction expectation, not proof that the current native solver admits it.
If actual contract inconsistency emerges beyond this fixture boundary, hold
the affected case and use the claims → paper/spec route; do not rewrite a
frozen identity or silently weaken the selector.

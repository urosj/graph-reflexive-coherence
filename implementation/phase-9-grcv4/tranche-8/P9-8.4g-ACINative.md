## Two implementation seams

1. At nonreference confirming geometry, `grc_v4_ci._analytic_residual` still
   calls `numerics.inverse(h)` before interval arithmetic. This constructs the
   full **exact** inverse even under `certified_arb_256_weighted_v1`. The existing
   `_iinverse` dispatcher and rigorous Arb interval component do not cover this
   call. Samples from the bounded large source run locate this cost inside
   FLINT inversion. This is not a physical-current inverse and is not solved
   by the already-certified physical flat solve.
2. The A branch computes the nonlinear exponent from `baseline[i][0].lo**2`.
   That only represents an interval operand correctly when its bounds coincide.
   With interval products, the entire baseline enclosure must be propagated
   through squaring and exponentiation, including zero-crossing and floor cases.

The [focused regression](../verification/test_p984g_aci_native.py) demonstrates
the second problem without a large campaign. On a one-edge A case with uniform
C, W=1, alpha=beta=0, gamma=1, chi=1/4 and zeta=1/2, the exact baseline is zero.
For trial J=1 the exact geometry residual is zero. Conservatively widening the
intermediate raw-baseline product from [0,0] to [-1,1] still encloses that input,
but the resulting computed geometry-residual interval has upper endpoint about
-7.62815e-11: it excludes zero. This is an injected enclosure-interface
counterexample, **not a failure observed on the frozen large fixture**.
The required inclusion assertion is retained as an expected failure until
corrected; a test runner's overall "OK" must not be read as conformance PASS.

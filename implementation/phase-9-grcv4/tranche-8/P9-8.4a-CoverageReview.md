## Comparison contracts and limits

The JSON contains five contracts: `exact_frozen`, `native_companion`,
`numerical`, `history_and_charge`, and `covariance`. Frozen resource tolerance
remains exactly zero. Canonical bytes, integer topology, ports, role mappings
and identities use exact comparisons. Numerical quantities use separately
bound norms, budgets, precision, domains, actual inputs and independent errors.

Representative **existing-subject** comparison ceilings are recorded below;
the machine record retains the full A `numerical_scope`, actual native solver

For independent interval comparisons, the full represented-output error must
meet the preregistered budget. A solve residual alone is insufficient; A_CI's
accepted earlier precision finding demonstrates that distinction. Dense
comparisons retain their stated bounded status. Effect claims additionally
need both complete errors and a declared ULP margin at the actual stages.
Charge admission retains each role's own target and rounding policy; no
clipping, history repair or hidden tolerance change is permitted.

New case budgets intentionally have **no automatic default**. They must be
bound by the cell's `.b`/`.e`/`.f` owner or larger prerequisite owner before
execution, with quantity, stage, role, norm, absolute/relative budgets, full
error method, source/graph/profile, timestep/horizon and oracle identity.
That is an explicit dependency in this completed inventory, not permission
to run an unbounded comparison. New A scientific scope retains its separate
oracle-before-runtime review.

The covariance contract retains the frozen namespace/role policy verbatim.
It transports rows, columns, branches, ports, external labels, event roles,
chirality and active phase. Numerical comparisons also transport reference
operators and history: A W is unsigned; currents/reference currents are
signed; H and Z transform by the relevant matrix conjugation. Raw digest
equality, column-only rotation or a stale phase is not covariance evidence.

The initial fifteen-test suite had two confirmed semantic blind spots: a
wrong phase on the negative D52 phase-one inventory row and a wrong child
owner could pass its semantic assertions. Reconstruction rejected divergence
from the correct generator, but did not establish the generator's correctness.
No incorrect retained assignment was found; these were in-memory mutations.

The strengthened suite uses an independently transcribed meaning table for
all seventeen expansions and three metamorphic subjects. It verifies every
degree, chirality, phase, module count, literal family, base/target pair,
normalization policy and exact child owner. Fixture IDs select the original
source rows independently of generated JSON pointers; pointers, JCS hashes,
requests, identities and comparison policies must all bind that same row.
All 400 cells must have the exact owner, applicability, eight named stages,
role-specific schedule and comparison contracts. Every file binding is
separately rehashed with the standard library.

Regression controls deliberately replace the generator with a wrong phase,
wrong owner or swapped applicability assignments that preserve 382/18 and
each family's counts. These regenerated records pass reconstruction against
the same faulty generator, and the independent semantic checks reject them.
Additional controls reject swapped source pointers, incorrect metadata, stage
substitution, reset scheduling errors, missing covariance contracts, omitted
carrier roles/layouts, foreign-family links, partial carrier reset, lost A W,
missing loss receipts and misrouted larger prerequisites. This establishes a
separate semantic check, not mathematical proof of future numerical execution.

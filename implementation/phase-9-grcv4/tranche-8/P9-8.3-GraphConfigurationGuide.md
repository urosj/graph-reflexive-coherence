numerical event examples use **10 vertices/9 edges → 17 vertices/16 edges**.
Those counts describe evidence, not a general maximum graph size. The native

The user's closeout request requires concrete preparation for **all ten

These are new configuration examples, with explicit parameter choices and
separately recorded numerical admission results. Preparation does not publish
an event or change the supported-profile registry. The
[validation](./P9-8.3-CloseoutValidation.json) distinguishes construction,

## What is fixed, configurable, or evolving

| Subject | Meaning of a change | Required action |
| --- | --- | --- |
| Constitutive equations, stage ordering, fixed port chart, history ownership | A different scientific/algorithmic contract | Review the changed contract and its implementation; retain the previous one |
| `kappa_H`, candidate coefficients, selector cutoff, solver tolerances, declared domains | A different configuration under an implemented contract, where the implementation supports it | Resolve fresh parameters/profile identities and rerun applicable admission; never reuse an old certificate |
| Graph, edge order/orientation, port allocation, reference weights, structural base, A descriptor | Different reference operands and identity dependencies | Rebuild graph/reference/descriptor/template identities and graph-dependent certificates |
| C, retained A W, persistent Z, clock, current/reset roles | Evolving authoritative state within the declared configuration | Use normal step/event/migration/reset operations and their checks |
| Accepted oracle, review, evidence hashes and their exact identities | A historical assertion about those bytes | Preserve them; create separately identified successor evidence |

`kappa_H` is a physical geometry coupling. A larger graph does not authorize
silently reducing it. A proposed reduction must be visible in a **new**
declaration before use; changing it during an existing run requires the
appropriate migration/lifecycle path. Candidate coefficients follow the same rule. A physical
step duration belongs to its explicit step request and applicable domain; it
need not change the profile identity when the declared contract admits variable
durations. The fixed native RG2b completion restricts its positive duration. A failed sufficient bound may be conservative;
failure alone proves neither that the equations are invalid nor that a root
does not exist. It still cannot authorize execution past that bound.

`R` is context-dependent. For PC and CI+PC, `radius` bounds the Frobenius norm
of the full star-supported carrier Z, not each matrix entry. For CI alone,
the radius in `CIBoundedDomain` bounds geometry displacement; it is not a
stored carrier. RG2b has its own section value/Lipschitz and base-state domains.
The PC resource radius `M` bounds **the whole vector** `||C||2`, and its W
interval constrains every incoming retained weight. These are not vertex
counts or cache sizes. Every number must be read with its norm and coordinate
system; A_RG2b's base coordinates include `Y=512 log W`.

Increasing PC R permits more history but enlarges the Hodge image. With unit
reference Hodge, the sufficient PC bound uses `rho=|kappa_H| R`, while CI+PC
must cover `rho >= 2|kappa_H| R`, including old Z and instantaneous source.
Positivity, conditioning, whole-chart source bounds, and (for CI+PC) root
self-map/contraction must all hold together. Enlarging M or R is not a purely
administrative edit. See the executable [PC envelope](../../../src/pygrc/models/grc_v4_pc.py)
and [CI certificate](../../../src/pygrc/models/grc_v4_ci.py).

The port rule counts **incidences**: each `(node,port)` is used once, and a
self-loop consumes two distinct ports. Thus `2m <= 9n` is necessary but not
sufficient; every node must fit independently. The structural owner allows
isolates, cycles and parallel edges when ports are unique. A particular
numerical certificate or event can impose stronger restrictions. The allocator
rejects a loop incident on the expanding source even though such a loop can be
a legal port graph.

## The prepared larger example

The source is a simple connected circulant on vertices `0..99`: each i has
oriented edges to `i+1,..,i+4 mod 100`. Tail ports are 1..4, head ports 5..8.
Move only the tail of `(50,54)` to `(0,54)`, using port 9 at node 0. The
unchanged offset-one cycle proves connectedness. There are exactly 400 edges,
98 degree-eight vertices, one degree-seven vertex and one saturated
degree-nine vertex. All 800 incidence tokens are distinct, leaving 100 unused
ports. An unmodified eight-regular graph would have **no saturated source**;
size and total spare capacity alone do not make an expansion candidate.

The request identifies source 0, D52, positive chirality, phase 3 and dyadic
shares `(1/2,1/4,1/4)`. The actual production **detached allocator** builds eight
module nodes and seven internal edges, giving 107/407, still with 301
independent cycles. Source saturation is established; the full fresh numerical
trigger remains an execution obligation. No fabricated postbeat flux or
successful receipt is supplied.

All examples use unit measures/reference weights, zero structural K4 base and
constant zero context. C profiles have no W; non-PC profiles have no Z. Each role starts at C=2 with a remote,
zero-sum dyadic pulse: current `+1/64` at 20 and `-1/64` at 70; reset `+1/32`
at 30 and `-1/32` at 80. Both have exact Q=200, but different states. Target
resources preserve every unaffected vertex and send source resource 2 to
the three satellites as `(1,1/2,1/2)`; other new nodes are zero.

The C_OS proposal retains `kappa_H=1/2` and the bounded C_OS physical coefficients,
but **explicitly selects a new cutoff `Lambda_C=2^-14`**. This is recorded in
the request and both newly resolved profiles. It is not a rewrite of the
accepted `2^-9` example. A connected, unit-weight graph has the conservative
reference Laplacian bound `lambda_2 >= 1/[n(n-1)]`: for a zero-mean vector,
`||x||2^2 <= n(range x)^2`, and a path of at most n−1 edges gives
`(range x)^2 <= (n−1) sum_edges (x_u-x_v)^2`. The cutoff is strictly below
`1/9900` and `1/11342`. Hence the reference selected sector is the constant
mode on both graphs. **This proof covers reference Hodge only.** Corrected
Hodge selector separation, current conditioning, split error and poststate
admission still need the production checks. Failure of this conservative
preparation bound for another cutoff would not by itself prove that cutoff
lies on the actual spectrum.

The package records two further decisive checks:

- Source `||B||inf=9`, `||B^T B||inf=17`, star-mask norm `17/2`; target values
  are 8, 16 and 8. For these simple graphs, a Gram row sum is `deg(u)+deg(v)`;
  the normalized star mask has half that row sum. Both graphs fail the native
  RG2b tree/size and Gram/mask hypotheses. Increasing only the vertex limit
  would leave the proof invalid. Cyclic **generic** RG2b examples use a
  different completion and do not bypass this check.
- Source current/reset squared resource norms are `400+1/2048` and
  `400+1/512`; target norms are `397.5+1/2048` and `397.5+1/512`. All exceed
  `16^2`. Each PC example therefore declares M=32, together with its own R, coupling,
  W interval and carrier initialization. Point containment alone is not the
  whole-chart envelope; the numerical records distinguish those checks.

One dense 400×400 binary64 matrix has 160,000 entries / 1,280,000 raw bytes;
the target's 407×407 matrix has 165,649 entries / 1,325,192 bytes. Those are
storage counts for one array, not memory or timing measurements. Exact rationals,
multiple matrices, interval iterations and serialized copies have additional
cost. The performance/cache review remains necessary.

## Reproduce and hand off the examples

From the repository root:

```bash
PYTHONPATH=src .venv/bin/python implementation/phase-9-grcv4/verification/prepare_p983_graph_admission.py
PYTHONPATH=src OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python implementation/phase-9-grcv4/verification/prepare_p983_all_realizations.py
PYTHONPATH=src:implementation/phase-9-grcv4/verification OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python -m unittest test_p983_graph_admission test_p983_all_realizations -v
```

The all-ten command rebuilds the concrete native states and pure transfers and
compares every retained byte-equivalent JSON value. `--family A_PC` selects one
example. `--write` regenerates proposed examples after an explicit request edit;
it does not edit accepted oracles. `--admit` executes the production numerical
read/certificate owners on source and target, independently for current/reset,
and writes `FAMILY-Admission.json`. It replays the retained native inputs;
`--write --admit` also rebuilds the pure transfer. The numerical probe budget
is 60 seconds per owner call by default (`--numerical-budget 0` removes it).
Setup is outside that budget, and a timeout records **incomplete**, with no
admission conclusion. The budget belongs to this verification harness; it is
not a profile parameter, scientific tolerance or runtime fallback. This can be expensive: repeated native
identity/geometry construction is included, and exact numerical work on a
400-edge graph is substantially larger than the accepted 9-edge fixture.

Each admission report names the owner and records its bounds or exact rejection.
An OS pass checks predictor/corrector/split; a PC report checks the uniform
envelope; a CI report checks the contraction domain; an RG report checks the
completion certificate. These have different scopes. In particular, a CI
certificate is not a computed root, and a PC envelope is not a completed
writer/step. No report alone establishes a trigger, event, receipt or continuation.

For subsequent lifecycle execution:

1. Reconstruct each native source from its own package, verify both role
   identities and charge, and perform full numerical readmission.
2. Evaluate the fresh trigger and form a request from the actual admitted
   source digest. A source beat changes that digest and the event identity.
3. Use the corresponding native operation owner for target reconstruction,
   both-role readmission, receipts and atomic publication. The detached target
   is the expected result of the pure transfer, never supplied authority.
4. Independently check the equations and attempt the declared continuation
   for both roles, recording the first rejection without clipping or retuning.
   Zero resource on new vertices does not guarantee a nonnegative first step.
5. Pressure covariance, boundaries and atomic failures before broadening any
   support claim. New A scope retains independent oracle-before-runtime review.

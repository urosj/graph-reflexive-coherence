## Evidence and what it establishes

- [Small execution](P9-8.5-COS-small.json): eight tests, including all five frozen
  failure classes on the real event receiver. Missing chirality, absent active
  phase, noncanonical inactive phase and a real source self-loop reject without
  publication. Natural reset-only OS split rejection has a passing current
  control. Independently injected current/reset resource corruption and a failure
  after prospective publication construction preserve the original publication
  pointer, full checkpoint, scientific/lifecycle identities and receipt ledger.
  Failure receipts are emitted without being appended to the successful ledger.
- Event replay reconstructs the exact checkpoint, target occupancy and all four
  receipts. Altered current/reset authority, request chirality, missing receipt,
  model identity and lifecycle identity are rejected. An incomplete C reference
  map is rejected even after recomputing its content, parameter and profile
  identities, so this is not merely stale-digest detection.
- The small event target is independently checked against the exact dyadic
  resource map for both histories. Its exact port reference/current/reset then
  seeds the existing generic lifecycle owner. One ordinary step is committed,
  the complete generic snapshot restored, reset executed, and the resulting
  snapshot restored again. Reset preserves clock and baseline, extends the
  receipt ledger, and restores the transferred reset authority. Missing ledger
  or commit records reject restoration. Injected late reset failure preserves
  the entire generic publication and the original event checkpoint.
- [Larger execution](P9-8.5-COS-large.json): one fresh replay of the accepted
  100-to-107-vertex event, ending with 407 edges / 814 distinct occupied ports.
  The real receiver readmits the source at construction and event execution,
  then both target roles. It produces the exact original checkpoint bytes,
  four receipts and lifecycle identity. No fresh trajectory or covariance
  campaign is counted; the existing 8.4h continuation remains its own evidence.

The small suite uses FLINT and fixed Arb256 except for separately declared exact
split controls. The larger replay uses FLINT, fixed Arb256 and worker-local
exact-content schema memoization, without numerical fallback. The retained
records report actual wall times against the 300/1200-second caps: **30.10 s**
for the small suite and **810.52 s** (13.5 minutes) for the larger replay.

## Important distinctions

At the tight reset-only threshold, the exact policy proves an OS split rejection.
The sufficient Arb256 split certificate instead raises
`CertificationInconclusive` with no inertia fallback. The suite verifies both
outcomes and full rollback. Inconclusive certification is not a proof of
mathematical inadmissibility and is not converted into a successful event.

The step/reset integration is an **explicitly linked two-owner composition**:
the native event checkpoint retains specialization identity, chronology and
event receipts; the generic owner begins from its exact target with a fresh
ledger, then owns step/reset receipts and commit preimages. Their seed and
checkpoint digests are retained. This verifies internal components and their
handoff, not a unified public GRC9V4 snapshot or import of event receipts into
the generic ledger. Tranche 9 still owns that public facade, complete serialized
specialization lifecycle, configuration and disabled compatibility.

No new G2/G3 support, all-graph numerical theorem, autonomous scheduling,
completion rule or acceptance of another family follows. This work adds
bounded lifecycle evidence, not new scientific claims or a debt adjudication.

## Reproduction and inspection

From the repository root, use `.venv` and
`PYTHONPATH=src:.:tests:implementation/phase-9-grcv4/verification`.

```sh
export PYTHONPATH=src:.:tests:implementation/phase-9-grcv4/verification
.venv/bin/python implementation/phase-9-grcv4/verification/tranche8_evidence.py status --family C_OS --checkpoint 8.5
.venv/bin/python -m unittest test_p985_cos_surfaces -v
```

The same selected status and bound source retrieval are exposed in the
side-tool API, notebook and **Check 8.5 lifecycle** browser action. Those commands
authenticate retained evidence and source identities; they do not run native
numerics. `run-small` and `run-large` explicitly execute the frozen campaign
with `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1`; they refuse to overwrite retained
results. Use a disposable checkout with the two result files absent for a new
run, preserving the accepted originals. A rerun has its own timing/digest.

Only compact observations and exact original checkpoint references are retained;
the larger checkpoint is not duplicated. No new file approaches the 1 MB raw
compression threshold. Routine test-development issues were fixture/API details
(inactive D30 phase, lifecycle `current` field, solver tolerance, separate
matrix-memo scopes for different policies); they caused no production fix or
relaxation of admission criteria.

The broad full-boundary wrapper was not rerun. Its previously reported interrupted
8.4i attempt is not relabeled a pass. Current source bindings and focused native,
retained-record, API and browser checks have their own explicit scope.
The five retained/API/HTTP pressure tests and two browser tests pass. They include
source drift, omitted manifest bindings, resealed coverage/scope mutations,
unsupported-family queries and clearing a stale successful browser result.

No new performance optimization was introduced. Existing FLINT/Arb256 and bounded
reuse were selected explicitly. Replay admits the identical source at construction
and again before expansion; profiling this repeated admission and serialization
is a candidate for the scheduled performance review. Any future reuse must bind
the full immutable subject, numerical policy and contract assets, preserve all
rejection/inconclusive behavior, and demonstrate identical output. This single
wall-time observation is not a controlled speed benchmark.

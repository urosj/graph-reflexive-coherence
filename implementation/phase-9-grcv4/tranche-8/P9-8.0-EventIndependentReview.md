## EC-F1 — the input record is validated, but the models actually consumed are not bound back to it

`validate_inputs()` checks the JSON recipe. `models()` then constructs source and target evaluators. The returned model objects are not independently compared with the validated record at the consuming setup. The interval evaluator obtains its graph matrices and parameter object from the represented model, so this omission can affect both sides of an otherwise independent arithmetic comparison.

Two separate mutations of `models()`, leaving the record, validator and mathematical constants unchanged, pass all four supplied test bodies:

1. Change the target's `internal/1` from port 2 to port 5 at both endpoints. The resulting ports remain unoccupied elsewhere. The current solver cannot distinguish this change in C_OS, but the declared positive-chirality transcript requires port 2.
2. Construct the target with `chi_c=32` instead of the recorded `chi_C=16`. The interval oracle follows the altered model parameter too. Continuation and all six effect comparisons still pass for that different law.

At the actual reset target, the second substitution gives a rigorously interval-separated current error greater than **2.3492831168e-8** and a resource-step error greater than **2.3379160420e-11** relative to the intended law. Both exceed the applicable 2^-40 output budget. The original tests certify the wrong model, not merely a differently rounded implementation of the intended model.

### Correction

Immediately after construction, bind each consumed model's node/edge roles, endpoint ports, index and candidate parameters to the validated record. Independently assemble and compare the small incidence, Gram, reference-identity and star-mask arrays. This is a local assertion for the pinned research construction, not a native profile/serialization scheme.

The proposed `assert_model_binding()` passes both original models and rejects thirteen altered-model controls: index, parameters, incidence, Gram, identity and mask on each graph, plus the target-port change. Use the assertion at the real consuming setup, not solely in an isolated helper test.

## EC-F2 — final reconstruction can change its own reference input

The new transfer consumer correctly isolates the source dictionary. Ordinary `advance()` also computes its independent exact-point result before calling the represented producer on `point.copy()`.

The final-read block does not: it calls `target.ordinary_os(..., target_point, ...)` before constructing the independent reference from `vector(target_point)`. The source/first-target effect block has the same ordering pattern.

A deliberate in-place defect was activated only at the final current-role target read: a target-core threshold between the ninth and tenth states selects that branch, then the producer adds 1/8 to its incoming resource array before reading it. All physical step inputs remain below the threshold. **All four supplied tests still pass**, and the branch is invoked exactly once.

The reported final-current error is approximately **1.3744313965e-15**. Against the untouched true step-ten state, the exact interval lower bound on current error is **4.6858314112e-9**, far above 2^-40. The verifier has rebuilt its reference on the changed input. The unmodified producer does not contain this defect.

### Correction

Use the same ownership rule already implemented for ordinary steps: preserve entry operands, hand separate work copies to the producer, and build the independent reference from the preserved entry. Apply this to the final reconstruction and the named-stage effect reads, without counting another physical beat.

The proposed `checked_read_only()` passes the original current/reset final reads, rejects the in-place shift for both roles by the entry-referenced current-error assertion, and preserves the caller arrays. It is a focused integration example, not production code.

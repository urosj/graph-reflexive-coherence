## Scope and actual execution

The [bound inputs](./P9-8.4b-AOSCases.json) cover all sixteen shared layouts:
D30/D45 with both chiralities, and D31/D52 with both chiralities and all three
phases. Each has distinct current/reset histories, ten positive target steps
per role and a final read-only OS pass. The two D52 phase-one requests retain
the separately reviewed `(1/4,1/2,1/4)` shares; the others use `(1/2,1/4,1/4)`.
No scalar parameter, timestep, horizon or error budget is relaxed.

One actual native source beat supplies the common source. Every event request
then binds that output's scientific identity and both W-history digests. The
target graph namespace, profile and state identities are reconstructed from
the resulting event identity, not borrowed from nominal oracle values. The
ordinary target trajectories start from the actual committed target in each
role, rather than restarting from a high-precision expected target.

Independent discrete expectations retain the frozen allocation and rebuild
the complete target reference. They check the exact resource map and charge,
old-edge W preservation, positive new-edge seeds, signed old-edge reference
currents and zero new-edge reference coordinates. Reference currents are
evidence, not replacements for solved target currents. The event executes four
read-only OS admissions (source/target × current/reset) before receipts; no
physical W write is permitted during it. Successful receipts, checkpoint state,
lineage and replay are checked separately from later continuation success.

## Numerical and stage checks

The [capture adapter](../verification/p984b_aos_capture.py) observes production
calls without replacing their calculations. It retains predictor/corrector
currents and Read-Back, generated/regenerated geometry, fixed-row rebuild
operands, continuity selection, W writer operands and final/restart reads.
The [runtime harness](../verification/p984b_aos_runtime.py) checks these against
the accepted paper-equation oracle and its separate interval evaluator.

Every ordinary step checks all nine accepted quantities against both the
nominal sequence and complete formulas evaluated at that step's actual C/W.
Current, baseline, C and Read-Back errors must be below `2^-40`; W and geometry
errors must be below `2^-48`. Read-only passes check their seven read quantities
without claiming a hypothetical C/W update was executed. Written-state final
and restart reads have separate interval checks at their respective geometries.
The OS split gate is checked independently, including its represented matrices.

The accepted pressure found that output tolerances alone miss subtle wrong-stage
substitutions. This adapter therefore requires the actual writer to consume
incoming W, final C and selected corrector J, exactly once. It requires each
geometry calculation to consume its own predictor/corrector Read-Back source,
and verifies the resulting staged star assembly. Descriptor observations also
distinguish the writer's incoming W from the new W used by final/restart reads.
Alternate Read-Back/flat surfaces and exact point/input identities are checked.
These observations complement numerical comparisons; neither is a substitute
for the other.

The interval evidence is pointwise for these finite trajectories, not a uniform
parameter tube, arbitrary-graph theorem, global accumulated-error enclosure or
new effect-separation theorem. The independent evaluator reuses accepted A.1
equations and interval helpers, not an independently authored second theory.
Typed identities and receipt hashing reuse production data codecs, while the
native current, OS pass and step are not invoked by retained validation.

## Portable verification

Run from the repository root with `.venv` and the declared `v4-flint` extra.
The interval evaluator also requires `mpmath==1.3.0`. The input record pins
source bytes, oracle acceptance, fixtures, budgets and test code; the output
records package versions. No machine-local input is required.

```bash
PYTHONPATH=src OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python implementation/phase-9-grcv4/verification/p984b_aos_runtime.py --check-retained
PYTHONPATH=src:implementation/phase-9-grcv4/verification OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python -m unittest test_p984b_aos_runtime.RetainedTests -v
```

The first command checks stored identities, actual operand captures, schedules,
nominal comparisons and certificate bindings/bounds. It does **not** rerun native
trajectories or recompute interval equations. Add `--recheck-numerics` for the
latter only. A fresh native run must use a new repository-relative output path:

```bash
PYTHONPATH=src OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python implementation/phase-9-grcv4/verification/p984b_aos_runtime.py --run --output implementation/phase-9-grcv4/tranche-8/P9-8.4b-AOSResults-rerun.json
PYTHONPATH=src:implementation/phase-9-grcv4/verification OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python -m unittest test_p984b_aos_runtime.NativeTests -v
```

`--prepare` was used once before this campaign to bind its inputs. It and
`--run` refuse to overwrite existing records. A rerun is new evidence, not the
original execution. Each case has a 120-second operational budget; timeout is
reported as incomplete, not a scientific rejection. Routine resumption needs
the retained check, not another full campaign or unrelated regression suite.

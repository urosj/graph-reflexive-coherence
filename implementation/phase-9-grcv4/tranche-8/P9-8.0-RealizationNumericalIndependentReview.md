## RN-F1 — mutable input operands move the certificate's reference state

### Finding

`evaluate()` passes its original C/W/Z arrays to `produce_step()`, then passes those same arrays to `certify_read()` and the independent continuity/writer evaluation. An in-place producer error can consequently alter the state being certified. The checker may then certify the update of the altered state rather than the input supplied at function entry.

Source locations: `test_p980_realization_numerical.py`, `evaluate()` lines 261–284 and `certify_read()` lines 164–185. The submitted `produce_step()` at lines 154–161 does not perform the tested mutations. This is a verification-boundary defect, not evidence that the unmodified numerical trajectories are wrong.

### Exact equilibrium counterexample

At a legal C_CI source equilibrium, pass `C = 3 * ones(n)`. A producer wrapper first executes `c += 0.125`, then calls the unchanged producer. The consumer accepts the result `C+ = 3.125 * ones(n)` and reports resource error **zero**. The exact ordinary update of the original input is `3 * ones(n)`, so its actual error is **1/8**.

This example requires no uncertain floating-point argument. Both constants are dyadic, the constant-state current and source are exactly zero, and the two compared resource states are distinct.

### Named-target pressure

The same issue was tested at the actual first-current-target inputs, obtained from each profile's enabled source step and prescribed transfer. Thirteen producer mutations are accepted:

These error lower bounds are exact interval-endpoint comparisons, displayed as decimals here. They exceed the applicable output budgets. No tolerance or parameter was altered by the mutations.

### Correction

Capture the incoming point operands before invoking the producer. Give the producer separate work arrays; retain untouched snapshots for certification. Both current and history/carrier comparisons must refer to the same entry state.

The accompanying `review_controls.py` demonstrates this separation around the existing consumer. It passes all six original profile inputs, rejects all thirteen mutations, and confirms that the caller's operands remain unchanged. It does not alter any numerical threshold.

Do not require optional exact-input enclosures to contain the rounded point operands: those enclosures can represent intended exact inputs in a composed error calculation and can legitimately exclude the rounded approximation. The issue is separation of the original numerical input from producer work storage, not elimination of that existing exact/represented distinction.

The note's chain equations correctly represent `Gamma_N = T^N Gamma_0` with terminal geometry `Gamma_0 = I`. They are not an instantaneous CI root or OS predictor.

From the full residuals, inverse subtraction gives

    E_X <= D_N (r_X + A_H E_H),

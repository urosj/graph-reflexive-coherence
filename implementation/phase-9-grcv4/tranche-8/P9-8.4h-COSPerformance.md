This is an implementation optimization, not a new scientific closure or a
successful large event. The original native prefix has two passing steps;
the event timed out at 1200 seconds. The native review summarizes that failure;
its artifact was removed at user request and is not a validation dependency.

## Exact replacement and limits

The [numerical-policy supplement](../../../specs/grc-v4-numerical-policy.md)
specifies the shared `src/` implementation: reuse a previously certified
`RN(A^-1 B)` only for identical exact A and B in the same operation and execution
policy. Conditioning under the caller's limit/witness, exact residual tests,
stage labels, complete point construction, both-role admission and publication
remain fresh. Nothing caches a current or an admissibility decision. The
solution is not inserted into the exact inverse cache. `MatrixReuse.FRESH`
explicitly disables reuse; no fallback or precision escalation was introduced.

The store is bounded by sixteen solutions/eight million scalar references,
discarded on operation exit, and excluded from continuation and wire state.
Dimension buckets use full exact equality, not approximate keys or digest-only
trust. This applies to all callers of the shared certified solve, including
A/C realizations, without claiming measured speedups for every family.

An initial eight-entry implementation hashed complete rational matrices. It
preserved read identities but was slower (about 161/156 seconds cold/warm),
with almost no expensive solve reuse. It was rejected. That exploratory trial
also detected a documentation binding change at final retention and published
no execution certificate. The corrected measurement is separate and binds the
final subject before execution; no old source identity is rewritten.

## Cold-kernel investigation (2026-10-19)

The [successor kernel profile](./P9-8.4h-COSKernelProfile.json.xz) uses the same
source-current input, FLINT and fixed Arb256. One cold read took **139.090 s**
and matched the complete retained predictor/corrector identities and split
evidence. No production implementation changed in this investigation; it adds
timing-only wrappers to the installed functions' syntax trees. This avoids
per-scalar profiler overhead while retaining their expressions and control
flow. The result is a diagnostic execution, not a new event or ordinary step.

| Measured work | Seconds | Interpretation |
| --- | ---: | --- |
| Arb LU itself | 13.405 | Eight non-diagonal solves |
| Arb output extraction and exact rounding-cell certification | 23.529 | Eight output loops; includes endpoint conversion and row assembly |
| Diagonal route and diagonal detection | 7.606 | Thirteen calls; not all are diagonal solves |
| Solve input conversion and exact-representation checks | 3.965 | Exact matrices, Arb input conversion, every input ball checked |
| General exact-matrix conversion | 15.476 | 87 calls outside the preceding solve-input bucket |
| Exact matrix products | 13.263 | 60 calls |
| Exact inertia | 13.277 | Four calls |
| Actual exact inverse computation | 8.410 | Two calls; retained path still contains exact work |
| Work outside the expanded instrumentation | 9.753 | Reduced from the earlier unattributed 49 s |

The table uses disjoint exclusive buckets, but intentionally omits smaller
categories; see the record for all counters. It does **not** claim that all
23.529 s are spent in LU or even solely in rounding-cell construction. Likewise,
matrix conversion includes allocation and scalar conversion, not just FLINT
arithmetic. Different runs' timings are observations, not rigorous speed bounds.

The suspected dead regularity construction is small: forming the exact
Laplacian and regularity block costs **0.927 + 0.620 = 1.547 s** inclusive in this
read. The certified branch does not consume those two objects; it calls
`c_regularity` instead. Removing that work is useful cleanup, not the main
performance fix. Do not attribute the full 8.410 s inverse bucket to it.

### Consequence for the next implementation

Prioritize the **shared exact-conversion and certified-output-rounding kernels**,
not another solver library or more identical-read caching. LU itself accounts
for only about 9.6% of this read. Investigate avoiding repeated conversion of
identical scalar values and repeated construction of identical rounding cells,
with bounded local storage and exact equality. Every output must still prove
whole-interval nearest/even cell containment; every solve must retain its exact
residual and conditioning checks. No rounded matrix multiplication or staged
read may be fused away under an exact-real equivalence argument.

These are opportunities, **not yet implemented or measured speedups**. A valid
successor must pressure ties/subnormals/overflow and changed operands, then
measure a fresh read and a changing-state step. Small diagnostic tests already
check dense/diagonal parity, singular and malformed-input failures, patch
restoration and retained read/source bindings. Reproduction uses the same
environment above with `p984h_cos_kernel_profile.py` (600 s cap, no overwrite).

The event successor remains paused for kernel work. Later it must retain
the same scientific inputs and original event cap. No campaign timing promise,
covariance completion or `.h` acceptance follows from this investigation.

## Scalar-kernel implementation and measured limit

The [fresh-read successor](./P9-8.4h-COSScalarReuse.json.xz) passes complete
pre-change predictor/corrector and split-evidence parity in **133.920 s**.
It uses the same scientific input, FLINT and fixed Arb256. No event or ordinary
step is credited by this read. Compared with the 139.090 s cold-kernel profile:

| Work | Before (s) | After (s) |
| --- | ---: | ---: |
| General exact-matrix conversion | 15.476 | 11.767 |
| Diagonal detection/solve route | 7.606 | 5.922 |
| Dense output extraction/certification | 23.529 | 24.352 |
| Arb LU | 13.405 | 14.096 |
| Whole read | 139.090 | 133.920 |

This is a modest approximately 3.7% observed total reduction, not a robust
campaign speed guarantee. In particular, cell reuse does **not** demonstrate
a dense-output-loop improvement. Different wall-time observations have normal
measurement variation; no event-cap feasibility is inferred.

The shared implementation reuses exact built-in scalar conversions within one
matrix conversion and exact rounding-cell boundaries within one solve. Each
store has at most 4096 entries, retains only successful values, and disappears
at return. Every incoming interval still undergoes the original endpoint and
whole-cell containment checks. The [implementation/proof note](../../corrections/GRCV4-CertifiedNumericalPolicy.md#p9-84h-scalar-kernel-reuse-2026-10-19)
records the equations and boundary conventions. No new arithmetic policy,
precision, inverse fallback, state, or admission cache is introduced.

Validation: 36 selected tests pass, covering exact Fraction/FLINT solves,
changed matrices/resources, two changing small native C_OS steps, ties,
subnormals, overflow, cache bounds/lifetime, and existing policy/solve-reuse
failure pressure. Historical execution records retain their original hashes;
the named Git-source adapter authenticates their old kernels rather than
rebinding those records to today's code.

Next: investigate dense-output extraction/certification at finer granularity,
preserving exact rounding proof. Repeated-scalar reuse alone is insufficient.
A large changing-state step and the event successor remain unexecuted on this
new kernel; do not substitute the small changing-step regression for them.

## Exact dyadic dense-output successor

The [dyadic result](./P9-8.4h-COSDyadicRounding.json.xz) replaces rational
endpoint/cell materialization in the dense Arb output loop with exact integer
nearest-even rounding of its outward dyadic endpoints. Equality of the finite
rounded endpoints proves whole-interval containment by monotonicity. It is not
a midpoint approximation. The rational diagonal path, fixed Arb256 solve,
conditioning, exact residual tests and all staged equations remain unchanged.
The [specification](../../../specs/grc-v4-numerical-policy.md#equivalent-exact-dyadic-output-certification)
gives the exact grid, quotient/remainder, tie, subnormal and overflow rules.

| Measured work | Scalar-reuse predecessor (s) | Dyadic successor (s) |
| --- | ---: | ---: |
| Dense-output extraction/certification | 24.352 | 4.888 |
| Arb LU | 14.096 | 13.821 |
| Whole fresh read | 133.920 | 113.725 |

Full predictor/corrector identities and split evidence match the original
retained baseline. The output loop is about 80% faster in this observation;
the complete read is about 15% faster than the scalar-reuse predecessor and
19% faster than the 141.010 s original read. These are bounded wall-time
observations, not parameter-wide or campaign guarantees. Exact inertia,
matrix products and LU now each cost about 13–14 s; there is no longer one
dominant dense-rounding bottleneck.

An isolated 12,000-ball seeded synthetic comparison also retains exact output
equality. Rational extraction takes 0.024 s and rational rounding 0.205 s;
the complete dyadic extraction/proof takes 0.058 s. Its separate 0.021 s
endpoint-float timing overlaps the rational rounding bucket and must not be
added to it. This synthetic measurement is not physical-fixture evidence.

Pressure includes 2,500 independent Fraction comparisons over signed
mantissas/exponents, exact ties and adjacent values, normal/subnormal/binade
transitions, finite overflow, huge exponents, 500 whole-ball comparisons, and
two changing small native C_OS steps against the original rational output
proof. The nine dyadic/scalar tests and eighteen existing certified-policy/
solve-reuse tests pass. The output proof never calls a fallback inverse.

The immediately preceding source/spec were not yet committed. Their exact
bytes are preserved as pinned compressed snapshots in `kernel-predecessors/`;
the historical adapter validates both compressed and decompressed identities.
The snapshots are evidence, never imported code. Original measurements and
source hashes are unchanged. Current execution has separate source bindings.

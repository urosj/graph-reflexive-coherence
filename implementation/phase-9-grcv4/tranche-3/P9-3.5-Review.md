# P9-3.5 — rejected-operation prestate preservation

P9-3.5 verifies full captured prestate preservation at the implemented rejection
boundaries. Implementation and validation are complete; user acceptance is
pending. The [execution record](./P9-3.5-ExecutionRecord.json) records the final
validation disposition. Entry follows the accepted P9-3.4 commit `12611fe`, bound
by [its acceptance record](./P9-3.4-AcceptanceRecord.json). That transition makes
eleven leaves dependency-ready and retains 23 eligible runtime paths. P9-3.5 is
not accepted by this transition; generic and specialization support remain empty.

## Scientific scope and ownership

The [specification](../../../specs/grc-v4-spec.md), sections **Complete-step
transaction** and **Errors and atomicity**, requires every failure to preserve
complete authoritative prestate. The [interface extension](../../../specs/grc-common-interface-v4-ext.md),
**Error and atomicity extension**, explicitly includes nonresource coordinates,
reset data, topology, history, caches and receipts. The
[paper](../../investigations/grc9v4-constitutive-design/drafts/2026-09-GRC-V4.md),
§§11.8–11.9 and E.3/E.12, forbids treating a valid provisional substage as a
committed state and forbids hidden fallback after invalid solves.

The accepted side tool's successor forensic queries are
`contract_provenance(D10.2-EC-PARENT-L-ATOMICITY)`,
`contract_provenance(D10.2-EC-PARENT-L-SINGULAR-FAIL-CLOSED)` and
`contract_provenance(D10.2-EC-PARENT-L-SNAPSHOT-RESET)`. Their source is the
[D10.2 registry](../../investigations/grc9v4-constitutive-design/decisions/D10_2FullSubstrateProvenanceAndPromotionAudit.json),
entries 44, 51 and 45 respectively. All return
`source_exact_contract_provenance` with `indeterminate_requires_review` claim
support. The trace identities and source/edge witnesses belong in the validation
manifest. The contracts require atomic authority, no hidden root regularization,
and restoration binding of state/profile/context/charge/reset. These queries
identify obligations; they do not prove runtime implementation.

The [ownership review](../tranche-1/P9-1.5-OwnershipReview.md) assigns provisional
evaluation to `grc_v4_step` and the sole authoritative commit/rollback to the
later lifecycle owner. The frozen crosswalk assigns P9-3.5 to the step source and
test paths. The current code has duration admission, rejected-result composition,
pure result comparison, provisional resource evaluation and cache consumption.
It has no executable V4 facade, complete candidate/root solve or lifecycle
transaction. Constructor/wire rejection is pre-operation validation, as the
spec explicitly distinguishes. This leaf tests preservation at those existing
surfaces without inventing a mutable model or a commit wrapper.

`preservation_snapshot` uses a detached tuple description of scalar bits and
the reachable container/record graph. Alias references are traversal ordinals,
not machine addresses. It is a test observer, not a new scientific serializer
or identity. Comparison includes malformed inputs without asking the production
codec to normalize or repair them. Returned failures and provisional records
remain values; no test claims that their mere existence proves rollback.
The actual persistent-ledger tests use two distinct content-valid successful
envelopes: reorder, duplication and an additional success entry reject; detached
equal entries in the original order pass. Their parent lineage is not validated
by the comparator. Reordered stage receipt IDs are a separate identity check.
Caller-supplied `observed_stage/code/solver` labels are checked for consistency;
they are not independently captured runtime provenance. Supplied failed solver
dispositions exercise the resource gate, not an actual failed candidate solve.

During test development the observer initially rejected internal mapping views
before reaching the operation. It now handles their concrete type and nested
sharing, with a mutation control. Negative C was initially attempted at an
unreachable resource-admission branch: the typed state constructor already
rejects it. Coverage now distinguishes that pre-operation rejection from actual
negative output after continuity. Neither development failure was a production
atomicity defect.
Request-pressure fixtures were also corrected to the schema's `context_value`
field, and a cross-realization stage fixture to the lawful common
`post_continuity` stage, so the intended rejection boundary is actually entered.

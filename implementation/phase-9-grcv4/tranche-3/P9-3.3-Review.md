## Arithmetic and stage boundary

The shipped charge evaluator requires `unit_vertex_measure_v1` in both the
profile charge identity and common measure declaration. It consumes a typed
vertex scalar in the graph's declared live-vertex order. Adjacent pairs add in
binary64, carrying an unmatched last value unchanged to the next level. Every
addition rounds separately; no sorting, compensated sum or global exact sum
replaces the prescribed reduction. Empty primitive charge is zero; this does
not admit an empty full reference domain.

After obtaining that binary64 `Q_actual`, admission compares
`abs(Q_actual - Q_target) <= absolute_tolerance + relative_tolerance * max(abs(Q_target), 1)`
exactly on the represented binary64 inputs using rational arithmetic. Only the
signed diagnostic residual is rounded once for the frozen receipt/observable
fields. This makes the written inclusive inequality decisive even when a
binary64 tolerance product would round upward or overflow. The receipt fields
are `target_charge`, `admitted_charge` and `residual`; the actual lifecycle
owner must supply `ReceiptCore`. An unrepresentable residual rejects as
nonfinite. A finite negative target is not independently forbidden by the
frozen schema; the declared tolerance still decides admission.

A positive-duration boundary first checks current and reset charges against
the common target. It then checks a typed selected result against independently
captured pre-read scientific/lifecycle contents, full reference, context,
operation and duration. The required selected stages are OS corrector, CI
trial, PC old history, CI+PC trial and RG2b section. CI and CI+PC require the
selected current to equal the current bound to that trial. A corrected OS Hodge
may differ from the pre-read Hodge while retaining the full same reference and
operation authority. A supplied `valid_root` label is not a root certificate;
the later stage provider owns residual, domain, branch and stratum truth.

Only that validated current reaches `C - dt * B J` once. The accepted
differential computes divergence; each resource coordinate then performs one
binary64 multiplication and subtraction. Result finiteness, nonnegativity and
charge precede exposure to a final-C consumer. Admission never alters the
candidate C. The returned immutable provisional state retains the old W_A and
Z_4. Reset data, time/index, receipt ledger and authoritative lifecycle are
not mutated. `ResourceBoundaryError` carries local stage/code and, for a
finite charge mismatch, the computed evaluation; it is not a complete failure
receipt or evidence of rollback of a live mutable model.

Current-selection serialization is a closed implementation-local envelope,
not a new frozen schema. Replay reads full inputs and recomputes the result;
supplied cached outputs are not accepted. `consume` requires independent exact
prestate and selection expectations before exposing the provisional state.
Like the existing local geometry cache, this is immutable in-process content
binding, not authentication against hostile Python memory modification.

## Precision witnesses and remaining owners

The literal four-vertex case starts with `(2**53, 1, 1, 1)` and target
`2**53 + 2`. A unit transfer from the first to the last vertex yields exactly
`(2**53 - 1, 1, 1, 2)`. Real charge is conserved, but the prescribed tree now
returns `2**53 + 4`. Zero tolerance rejects with residual 2; absolute tolerance
2 accepts the unchanged candidate. This separates continuity's arithmetic
from charge admission and guards against hidden repair or silent tolerance.

For the rounded-tolerance witness, target 3 and its next larger binary64 value
have separation `2**-51`. With relative tolerance
`0x1.5555555555555p-53`, a binary64 multiplication by 3 rounds to that separation,
but the exact product is smaller. The gate rejects; the next larger tolerance
accepts. The independent oracle uses exact fractions, not the production gate.

The 48 covariance cases deliberately use exactly representable scales.
Canonical-order charge reduction and the accepted differential's native sum
are not a theorem of bitwise permutation invariance at arbitrary scales or
across Python summation implementations. Underflow may round a transfer away;
there is no hidden accumulated remainder. P9-3.4 owns broader conditioning,
signed/permutation and charge-precision characterization, including repeated
clusters/invariant projectors and the already retained mixed-scale star witness
`(5e-324, 1e150)`. This leaf neither changes that star arithmetic nor closes its
open finding.

P9-3.5 owns full rejected-operation preservation. Tranche 4 owns the actual C
current/OS provider and facade/complete-step admission and consumption;
Tranche 5 owns A_OS. Tranche 6 owns actual CI/PC/CI+PC/RG2b roots, invariant
carrier domains and their writer relationships. Full final-C reconstruction,

### Expanding shared input records

This standard-library recipe recreates the original three numerical input
records in an ignored repository-local working directory. It verifies each
shared file before reading it. The expanded `subject.base_commit` and
`subject.patch` recover each tested revision; verify the resulting files against
`subject.tracked_file_sha256`. Use a separate checkout of the recorded base,
and do not apply a historical patch over the current working tree.

```bash
.venv/bin/python - <<'PY'
import hashlib, json
from pathlib import Path
leaf = Path("implementation/phase-9-grcv4/evidence/P9-3.3").resolve()
output = Path("implementation/investigations/grc9v4-constitutive-design/tools/exploratory-side-tool/tool/generated/p933-expanded-inputs")
output.mkdir(parents=True, exist_ok=False)
def shared(record, ref):
    path = (record.parent / ref["path"]).resolve()
    assert path.is_relative_to(leaf)
    assert hashlib.sha256(path.read_bytes()).hexdigest() == ref["sha256"]
    value = json.loads(path.read_text())
    for key in ref.get("pointer", "").split("/")[1:]:
        value = value[key.replace("~1", "/").replace("~0", "~")]
    return value
for name in ("validation", "audit-1-native", "audit-1-followup"):
    record = leaf / name / "inputs.json"
    data = json.loads(record.read_text())
    subject = data["subject"]
    if "reference" in subject:
        base = shared(record, subject["reference"])
        hashes = {p: h for p, h in base["tracked_file_sha256"].items()
                  if any(p == s or p.startswith(s + "/") for s in subject["scopes"])}
        sections = ["diff --git " + s for s in base["patch"].split("diff --git ")[1:]]
        patch = "".join(s for s in sections if s.splitlines()[0].split()[2][2:] in hashes)
        data["subject"] = {"base_commit": base["base_commit"], "patch": patch,
                           "tracked_file_sha256": hashes}
    elif "reference" in subject["tracked_file_sha256"]:
        hashes = subject["tracked_file_sha256"]
        subject["tracked_file_sha256"] = shared(record, hashes["reference"]) | hashes["overrides"]
    if "reference" in data.get("resource_replay", {}):
        data["resource_replay"] = shared(record, data["resource_replay"]["reference"])
    (output / (name + ".json")).write_text(json.dumps(data, indent=2) + "\n")
PY
```

The expanded input hashes in the execution record identify the original bytes.
Stored capture runners describe the original procedures and their original
record layout. For numerical replay of the current consolidated packet, use
the direct repository-input recipe above or the unchanged tests below.

## Implementation decisions

Production lives in `src/pygrc/models/grc_v4_geometry.py` and
`src/pygrc/models/grc_v4_transport.py`; their tests use the corresponding
`tests/models/test_grc_v4_*.py` paths. No core storage, legacy model, shared
serialization, record schema or facade export changes are made.

The serialized live-node and oriented-edge arrays define coordinate order.
There is no implicit sort, reorientation, slot compaction or allocation.
Node IDs are strings or safe integers. Integral float IDs normalize to integers
on both direct and wire paths; booleans, unsafe integers, nonintegral or nonfinite
IDs and negative zero reject. Numeric `1` and string `"1"` remain distinct.
Empty node labels are allowed by the frozen graph schema. Edge IDs are nonempty
and unique, and every endpoint must be live. Isolated vertices, parallel edges,
self-loops and empty spaces have explicit behavior. A loop contributes zero
incidence and occurs once in its vertex star.

Positive tail-to-head flux has outward divergence `+1` at its tail and `-1` at
its head, with `d0 = B.T`. The source contract permits a coordinate orientation;
this implementation declares the sign choice in its descriptor. The exact
backend `oriented_incidence_d0_equals_BT_v1` with `closed_no_flux_v1` executes
these primitives. Unknown backends or boundary policies reject. Common measure,
context, units, normalization and other declarations participate in differential
identity, without implying execution of their future profile-level evaluators.

Graph digest uses the frozen `grc-graph-sha256` JCS rule. Orientation,
differential, pairing, flat and mobility descriptors use explicitly versioned
implementation-local preimages, listed in the source map. Their roles and full
mathematical inputs are bound. These descriptors neither extend the frozen wire
schema nor certify stage/cache freshness. Reconstruction requires the serialized
graph, resolved common/candidate declarations, pairing matrices and retained A
values; a digest alone cannot reconstruct omitted data.

Tuple storage retains no caller-owned array. Private copied dictionaries expose
read-only index lookups. New modules reuse the existing V4 `_number`, `_vector`,
`_text`, JCS/schema and lazy dependency guards, plus immutable parameter records.
The source map gives each consumed/rejected symbol, source hash and reason.
Legacy mutable graph wrappers, monotone allocation, tombstone slots and non-JCS
serialization do not supply scientific authority to these primitives.

Hodge inputs must be finite, exactly symmetric and strictly positive definite
as exact dyadic matrices. The audit-1 correction below replaces the original
binary64 Cholesky screen with exact local validation. Flat applies the paired realization
`G_J = H1_form^-1` by direct solve; sharp applies `H1_form`. Typed pairings use
separate vertex and one-form spaces. Numerical storage and all results detach
from inputs. Arithmetic zero has the canonical `+0` representation; negative-zero
inputs still reject. There is no symmetrization, pseudoinverse, damping, repair
or conductance floor. Nonfinite arithmetic and zero/overflowed mobility factors
reject. NumPy `2.4.6` is now an explicit pinned `v4` extra, as reviewed; it is
not supplied implicitly by matplotlib.

A mobility reads positive retained `W_A` in live edge order and multiplies it by
A's `eta`, without updating that authority. C mobility reads only the exact
profile map `W_C_tr` and `eta_C`; there is no selector or geometry argument.
C's `E_H` structural constructor returns a distinct `OneFormHodge`, while `E_M`
returns `CandidateCMobility`. Equal matrix entries cannot substitute their types
or authority. Full C stage/constructor bindings remain with P9-3.2/P9-4.1.

**Disposition:** these public Hodge constructors admit locally positive
matrices. `_require_positive_definite` now implements
`exact_binary64_sylvester_bareiss_v1` for every dimension. It does not infer
positivity from numerical factorization, inverse completion, a determinant-only
test, an absolute epsilon or a conditioning estimate.

The algorithm's justification is explicit:

1. Each retained finite binary64 entry has an exact integer/power-of-two ratio.
   The largest denominator is divisible by every denominator. Multiplication
   by this common positive denominator gives an integer matrix `A` with the
   same definiteness as the retained matrix, without rounding or modifying it.
2. For the symmetric integer matrix, let `Delta_k` be the determinant of its
   first `k` rows and columns, with `Delta_0 = 1`. Fraction-free elimination
   starts with `previous = 1`. At step `k` (zero-based), its pivot is
   `Delta_(k+1)` and each trailing entry is updated as
   `(pivot * entry - column_entry * row_entry) / previous`, then
   `previous = pivot`. The determinantal identity underlying this recurrence
   makes every division exact while earlier pivots are nonzero. The code
   checks the integer remainder and fails closed on an invariant violation.
3. A nonpositive pivot rejects immediately. If all pivots are positive,
   exact symmetric elimination has positive diagonal factors
   `Delta_(k+1) / Delta_k`, so its quadratic form is positive on every nonzero
   vector. Conversely, a positive definite symmetric matrix has positive
   leading principal determinants. This is Sylvester's criterion; there is
   no unresolved floating-point sign decision. Positive diagonal and empty
   matrices have direct equivalent checks and avoid elimination.

The recurrence is the integer-preserving elimination described by
[Bareiss (1968), *Sylvester's Identity and Multistep Integer-Preserving Gaussian
Elimination*](https://www.ams.org/mcom/1968-22-103/S0025-5718-1968-0226829-0/S0025-5718-1968-0226829-0.pdf).
The implementation and derivation above define the actual local procedure;
the reference does not add a model or profile policy.

Admission therefore depends on the exact matrix, not the BLAS factorization
outcome. Positive rescaling and signed permutation congruence preserve its
mathematical decision. Retained values, positive-input content identities,
direct NumPy solves and binary64 pairing arithmetic are unchanged. Exact
positivity of the retained matrix does **not** make rounded bilinear evaluations
or solves exact, guarantee their accuracy or finiteness, or admit a full
profile/conditioning/stage domain. `POSITIVITY_POLICY_ID` names this local
validation procedure; it is not a frozen wire parameter or cache certificate.
This decision supersedes only the positivity-screen statement in the historical
source map's `implementation_decisions.numeric_backend`. That source map and
its exact scientific/forensic bindings remain unchanged as prior evidence.
No symmetrization, jitter, clipping, repair, pseudoinverse or hidden tolerance
is introduced.

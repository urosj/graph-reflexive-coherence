## Star-product correction and limits

The inherited [P9-3.2 audit](../evidence/P9-3.2/audit-1-followup/run.json)
identified adjacent ordinary edges with form `(5e-324, 1e150)`. Their overlap
coefficient is 1/2. The pre-fix production implementation at `9409252` evaluated
`(weight * a) * b`. Its first product rounds to zero, losing the representable
coupling `2.4703282292062327e-174`; swapping the two edges retains the coupling.
The new regression was executed against that production code and failed with
`0.0 != 2.4703282292062327e-174` before correction. That failure is reconstructible
from the named Git source and the retained new test; the older published audit
remains the original historical failure evidence.

`StarAssembly` now forms the exact dyadic product of the binary64 overlap
coefficient and both binary64 form entries, then rounds once to binary64.
The coefficient is still `count / sqrt(m_i*m_j)` using the existing binary64
sqrt/division, and its diagonal is exactly one. This changes evaluation of the
same assembly law. It adds no gain, damping, clipping, PSD repair or scientific
coordinate. Multiplication cannot lose a representable component through an
intermediate range failure, and swapping/signing the two operands commutes with
the final rounding. A final unrepresentable product raises `ValueError`;
a truly underflowed product remains canonical zero. Temporary rational values
are discarded; the matrix retains binary64 tuples.

The descriptor changes from `grcv4-vertex-star-cooccurrence-v1` to
`grcv4-vertex-star-cooccurrence-product-v2`. Last-bit changes are possible even
at moderate scales, especially loop/ordinary pairs with an irrational cover
coefficient. Existing scientific/profile law and frozen release bytes remain
unchanged; the new source and derived-cache identities distinguish arithmetic
executions. Old cached outputs cannot acquire the new identity by rehashing.

The audit witness has 100% relative error in the old coupling, while the exact
normwise ratio is coupling divided by roughly 1e300. That ratio is itself below
the binary64 range, so the retained diagnostic is an exact fraction string.
A normwise floating zero was never a valid componentwise accuracy certificate.
After correction its tiny diagonal square still truly underflows to zero;
the represented matrix has a negative exact determinant because its off-diagonal
is nonzero. The real assembly theorem is PSD, but independently rounded entries
do not universally preserve it. `H_profile` still independently checks the exact
affine total and its stored binary64 Hodge. No missing diagonal is manufactured.

## Numerical envelope

Exact comparisons cover graph order/orientation, immutable identities, cache
provenance, rejection dispositions, dyadic positivity, represented-product
rounding, prescribed charge reduction and the written tolerance inequality.
Dense solves use NumPy's direct solve with no fallback. For the explicit
well-conditioned dense family, the test bounds relative infinity-norm forward
error by 2^-45 and scaled residual by 2^-49; signed-coordinate forward comparison
uses 2^-44. These are test envelopes for the stated fixtures, not a universal
runtime condition certificate. Near the SPD boundary, the exact analytic
condition number scales the forward bound, capped at 1/8 for this pressure
family. Small residual alone is not a forward-accuracy guarantee.

For the separated repeated cluster, gaps are 4, 2^-12, 2^-28 and 2^-40.
The spectral-projector operator-norm error bound is
`32 * eps * lambda_max / gap`, with `eps = 2^-52`. Within-cluster rotations are
compared at absolute 2e-15. At zero boundary gap a rank-two sector is not unique;
no signed/order eigenvector convention can fix that missing mathematical
selection. The nonidentity physical-metric fixture uses absolute 2e-13.
The dense rational follow-up observes worst projector error
`7.258485891457125e-4` at gap `2^-40`, against bound
`7.812500000007105e-3`; its input infinity-norm error is at most about `1.11e-16`
for that direction/gap. The structured exact fixture alone remained near
machine precision and would not characterize this conditioning sensitivity.
The largest well-conditioned solve forward error was `6.48e-16`, with scaled
residual `7.46e-17`; the near-SPD family reached forward error `1.86e-9`.

Actual C selector cutoffs, strict-gap decisions and current-block conditioning
certificates must be executed by P9-4.2/P9-4.5 using these independent comparison
principles. This leaf deliberately does not count a NumPy analysis fixture as
that future production execution.

Divergence uses the recorded CPython built-in `sum` in each incidence row,
with binary64 products before aggregation. CPython/backend version is therefore
part of the experimental envelope. Same-sign intermediate overflow can reject
an exactly cancelling row, while alternating order succeeds. Charge uses its
separate, prescribed adjacent pairwise tree and does not inherit Python `sum`.
No algorithm, sorting, compensating fallback or charge policy was changed to
make the cancellation controls pass.

The paired precision limits from [P9-3.3](./P9-3.3-Review.md#independent-audit-follow-up)
remain: `(2**53, 0)` with a half-unit transfer may gain an exact stored sum of
1/2 while the charge residual is zero. `(1e20, 0)` with 100 unit primitive
compositions gains an exact stored sum of 100 with zero rounded residual at
every composition. Conversely, an exactly conservative four-vertex transfer
can have residual 2 and fail a zero-tolerance gate; other vertex orders yield
zero. These are prescribed precision effects, not authorization to repair C.
Subnormal and half-ulp controls also include transfers that round away and
negative provisional resources that fail charge admission.

## Geometry and local domain

`K4Tensor` retains baseline and increment separately. Computing an increment
by subtracting two rounded large totals could lose it; `H_profile` consumes the
explicit increment and verifies the baseline against the supplied reference.
The baseline itself need not be positive definite. Positivity belongs to the
resulting Hodge. Neither a tensor nor common star assembly is candidate mobility.

The implementation-local coordinate contract is
`grcv4-vertex-star-dense-row-major-v1`. It stores the selected exact vertex-star
bilinear space in a dense edge-square matrix: entries joining edges with no
common endpoint must be zero. Symmetry, finite values, graph coordinates and
support are checked for both baseline and increment. For PC/CI+PC, the existing
flat `Z_4` value uses exactly `n_edges**2` row-major coordinates in that same
space. This bounded representation is explicit in the reference envelope; it
is not a new frozen wire field or a universal restriction on future graph-local
covers. A sparse structural/Hodge matrix may have a dense inverse; inverse
response is never masked to the assembly support.

The common assembly computes the stated sum of normalized local outer products.
A loop belongs to one star, an ordinary edge to two, and parallel edges retain
their distinct IDs. For each pair its weight is the star co-occurrence count
divided by `sqrt(m_i*m_j)`. This algebraic form preserves the diagonal partition
exactly, avoiding a spurious diagonal factor from squaring an approximate
inverse square root. It consumes a lowered `OneForm` and includes no candidate
adapter or gain. The candidate source producers remain with their later owners.

The reference package binds the full ordered graph, complete profile and
parameters, typed context, baseline preimage and stable-edge Hodge preimage.
The shipped unit measure gives `H0_ref = I`; `H1_ref = diag(W_ref)` and the
physical-flux flat map uses its inverse. C reference values must agree with
`W_C_tr` by stable ID even when a different map has a correctly recomputed
reference hash. `eta_C * W_C_tr` cannot replace the structural reference.
The frozen identity fixture with nine edge weights and a two-square baseline
remains a valid declaration fixture; it is rejected as a complete graph-domain
reference rather than silently resized.

The implemented context is precisely `constant_zero_context_v1` with an empty
payload. Unknown geometry, star-cover, overlap, flat/sharp solver, measure,
context or units declarations reject. The candidate adapter ID is bound to the
selected A/C family; binding the ID does not execute its later source producer.
Current solver, gauge and candidate-domain declarations remain identity inputs
until their actual consumers exist.

`H_profile(K_4, *, reference, context, profile)` has the canonical signature and
implements `H1_plus = H1_ref + kappa_H * increment`, retaining `H0_ref`. The
reference is positive, so Sylvester inertia under congruence makes positivity
of this affine matrix equivalent to `I + Theta > 0`. Exact dyadic products and
sums are checked with the accepted fraction-free Bareiss gate before rounding;
the retained binary64 result is independently checked by `OneFormHodge`.
Thus a small positive mathematical result that rounds to a singular matrix
still rejects. A negative or zero mathematical affine result cannot be admitted
by a favorable rounded factorization. Zero gain or zero increment returns the
reference exactly, including a nonzero baseline.

Actual affine arithmetic uses binary64 multiplication followed by addition;
zero is canonicalized and nonfinite results reject. Tiny nonneutral changes
can round away. Irrational overlap weights and numerical solves also round;
the mathematical PSD assembly formula is not a theorem that every rounded
matrix has exact PSD inertia. Independent oracle tolerances are test tolerances,
not profile admission thresholds. There is no symmetrization, clipping,
pseudoinverse, damping, hidden diagonal floor, or resource repair. The selected
current solver's `conditioning_limit` is not reinterpreted as a new Hodge
condition-number policy. Conditioning and current/root admission retain their
assigned later consumers.

## Stage provenance and cache consumption

A stage input holds full reference/profile/context data, actual Hodge, detached
current and reset authoritative values, `Q_target`, ordered receipt IDs,
operation identity, step index, time, duration, stage, evaluation index and
trial current. Reset, scientific-state and lifecycle IDs are recomputed from
their exact frozen preimages; import rejects a supplied mismatch. The fixed
zero context has no trajectory-varying context value (`context_value_digest`
is `None`).
The graph includes IDs, coordinate order and orientation. Current/reset shape,
signs, history presence, local carrier coordinates and applicable positive
geometry image are validated. Zero duration passes the same geometry checks.
Frozen preimage identity and valid receipt-ID grammar do not authenticate a
caller or the underlying receipt payload ledger. The later operation owner
must capture expectations independently from its admitted live lifecycle.
Charge-target identity is bound here; charge equality is the later charge gate.

The allowed stage vocabulary has explicit family compatibility. OS predictor
uses the reference; corrector inputs are distinct even if their matrices and
outputs are identical. There is no second-corrector label. CI and CI+PC require
trial current and bind each evaluation index and trial geometry. PC read
geometry and its cached `H_profile` operand must come from old committed
history. Noniterated stages require evaluation index zero. These are checked
stage inputs, not claims that the full predictor/current/root/writer sequence
has executed.

The cache registry contains exactly six actual producers: `d0`, `divergence`,
`flat`, `sharp`, `star_assembly` and `H_profile`. It accepts typed operands and
computes its immutable output; there is no caller-supplied result or callback.
Consumption requires independently captured expected inputs, operation and
operand. Serialization includes the complete reconstruction payload and a
versioned local content hash. Import compares fresh canonical expectations
before numerical rebuilding, recomputes the specified primitive, and checks
both the resulting payload and digest. A correctly rehashed false output,
wrong role, Boolean/numeric alias, unknown field or foreign stage rejects.
A content hash is integrity data, not execution authority. Direct inspection
of a cache's value does not perform its required consumption check.

These local envelopes are separate from the frozen scientific/lifecycle wire
schemas and support registry. `GeometryStageInputs.from_payload` reconstructs
a typed local subject; it does not grant full lifecycle, charge, solver or
migration admission. Reference and stage reconstruction require full values,
not merely self-consistent digests.

### Reconstruct and export the audit follow-up

From the repository root, extract and hash-check the original audit and the
two diagnostic/export programs using the standard library. Script source is
retained in the approved evidence JSON envelopes; no additional executable
runtime target is introduced.

```python
from pathlib import Path
import hashlib, json
evidence = Path("implementation/phase-9-grcv4/evidence/P9-3.2")
scratch = Path("implementation/investigations/grc9v4-constitutive-design/tools/exploratory-side-tool/tool/generated/phase9-portability/temporary/p932-reconstruction")
scratch.mkdir(parents=True, exist_ok=False)
original = json.loads((evidence / "audit-1-inputs/inputs.json").read_text())
programs = [x for x in original["attachments"] if x["filename"].endswith(".py")]
for group in ("audit-1-native", "audit-1-followup"):
    programs += json.loads((evidence / group / "inputs.json").read_text())["programs"]
for item in programs:
    data = item["utf8_content"].encode("utf-8")
    assert hashlib.sha256(data).hexdigest() == item["sha256"]
    with (scratch / item["filename"]).open("xb") as output:
        output.write(data)
```

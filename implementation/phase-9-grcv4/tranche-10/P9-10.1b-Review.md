## What is tested

[Three tests per family](../verification/test_p9101b_target_compatibility.py)
cover the original target round trip, its explicit basin successor round trip,
and rejection/rollback pressure. Independent family processes use FLINT and
the existing explicit `legacy_exact_v1` numerical policy.

The V3 counterpart is independently constructed from the saved target graph,
port ordering, resources, clock and declared incoming weights/flux. It is not
initialized from the adapter's output. A separate scalar row/initializer oracle
checks the incoming-stage base conductance. Both implementations then execute
native step → reset → step, with exact result, complete snapshot (including
signed zero), and observable equality at each stage. Patches assert that neither
enabled V4 evolution nor the new basin classifier enters disabled delegation.

The retained target happens to have equal current/reset resources after its
prior reset; this is reported explicitly. The two incoming weight/flux vectors
are deliberately distinct. Actual native evolution then produces distinct
current/reset resources before return. Return checks each role independently:
C resources map in graph order; Candidate A uses fresh independently calculated
initializer history; A_PC zero-initializes its carrier after the declared loss.
These crossings do not claim lossless preservation of A history or carriers.
Positive enabled evolution and reset follow successful return. Disabled and
enabled checkpoints replay exactly, including the committed parent-receipt DAG.

Six rejection controls per family are separate from the successful surfaces:

- A reset-only invalid incoming weight, with the current declaration valid.
- Native weighted-least-squares Hessian mode: its native prestages execute, but
  the V4 crossing correctly refuses it because the crossing requires fixed rows.
- Injected late entry publication failure.
- Substitution of the old source graph for the exact expanded return target.
- Injected reset-only return readmission failure after the current role passes.
- Injected late return publication failure.

Each preserves the entire publication pointer, snapshot and successful journal.
Expected failures emit uncommitted failure receipts; injected unexpected late
exceptions propagate while preserving publication. Altering the retained reset
flux declaration is rejected on replay. These controls demonstrate refusal,
not successful compatibility in the excluded domain.

## Boundaries and reproduction

This establishes the four declared surfaces for each exact target and its
explicit basin successor: 16 v1 target cells and 16 separate v2 target cells.
It does not fill the other 24 source-matrix cells, establish arbitrary target or
family-wide compatibility, authorize the frozen all-forty umbrella capability,
or grant G4/full conformance. Existing CI resolution and pointwise A_PC numerical
limits remain unchanged. No additional topology event or general ATC is tested.

The [checker](../verification/p9101b_target_compatibility.py) authenticates retained
records, source bindings, exact identities and coverage. `--check` performs no
native trajectory rerun. The side-tool exposes the checked result and indexed
sources at `/api/tranche10/targets` and `/api/tranche10/targets/source`, with a
browser panel and notebook `expanded-targets` cell. It exposes bounded acceptance
and does not erase P9-9.6's historical holds.

```bash

PYTHONPATH=src:.:implementation/phase-9-grcv4/verification .venv/bin/python -m unittest test_p9101b_target_surfaces -v
```

For a fresh run, select one family and a **new** output path with `--run --family
C_OS --output <repository-relative-path>.json`; repeat for the other three in
parallel. The runner compresses automatically above 1 MB and refuses to overwrite
existing evidence. A rerun is a new execution, not a replacement acceptance.

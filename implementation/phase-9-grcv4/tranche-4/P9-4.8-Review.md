## Gate findings

**G2-COS-INTERFACE.** The [family specification](../../../specs/grc-v4-spec.md#class)
requires `GRCV4(GRCModel)` and the common interface plus the V4 extension.
[grc_v4.py](../../../src/pygrc/models/grc_v4.py) currently defines request records.
[CandidateCOSOperation](../../../src/pygrc/models/grc_v4_lifecycle.py) is an
internal receiver, as its own docstring and the accepted P9-4.5 review state.
It does not implement `GRCModel`. Missing common methods include `from_config`,
`get_params`, `list_capabilities`, `compute_observables`, `step` and `run`;
missing V4 methods include `run_v4`, active profile/model identity and lossless
profile/model discovery. Existing methods with similar names still need their
public signature and projection contracts checked. A wrapper name alone cannot
close this finding: default requests, stage-tagged observables, capabilities,
restoration and common result projections must have actual executable behavior.
The [P9-2.6 review](../tranche-2/P9-2.6-Review.md) explicitly deferred that work;
its foundation-only no-facade assertions cannot serve as final conformance tests.

**G2-COS-PARENTS.** The unresolved [P9-2.4 parent-reference obligation](../tranche-2/P9-2.4-Review.md)
remains open. The [interface receipt contract](../../../specs/grc-common-interface-v4-ext.md#step-results-receipts-and-observables)
defines `parent_receipt_ids` and acyclic receipt/commit/envelope hash construction.
The [paper](../../investigations/grc9v4-constitutive-design/drafts/2026-09-GRC-V4.md),
§12.5 and E.5, requires ordered source/target profile pairs. The accepted side-tool
[contract registry](../../investigations/grc9v4-constitutive-design/decisions/D10_2FullSubstrateProvenanceAndPromotionAudit.json),
`/normative_equation_contract_registry/50`, says
`migration_and_event_receipts_bind_ordered_p_source_p_target`. None of those
statements chooses historical versus intra-commit parent scope or its ordering.
This review reads the accepted source row directly; it does not claim a new
side-tool execution or promote provenance to runtime acceptance.

P9-4.7's tested local convention is precise: ordinary steps use the previous
ordinary primary; administrative/crossing operations use the latest primary;
the four operation receipts share parents. That convention may be defensible,
but scoped acceptance explicitly excluded generic parent-DAG conformance.
Hash recomputation, chronological ledger checks and identical continuation do
not resolve the missing normative decision. Neither all-history parents nor an
intra-commit-only restriction may be adopted implicitly. Authority resolution
must cover missing, foreign, forward, self, cyclic, duplicate and reordered
references, followed by corresponding runtime pressure.

**G2-COS-FIXTURES.** The [catalog execution contract](../../../specs/grc-v4-conformance-fixtures.json)
and [accepted support register](../tranche-1/P9-1.4-SupportAndDependencies.json)
require the applicable product over nominated **complete** profile identities.
There is currently no nominated complete-profile support population with that
reconciled product. Existing parameter/domain/graph fixtures establish substantial
component and operation evidence. Changing solver tolerances, zero controls,
reference maps or other identity-bearing parameters changes the profile; their
passes cannot be pooled under the family label `C_OS` or a frozen seed ID.
The required result fields include profile/model/parameter identities, pre/post
digests, operation and solver dispositions, committed status and receipt IDs.
Counts of test methods and passing source manifests do not supply those rows.

`COMMON-STALE-CACHE` needs evidence reconciliation before a missing test or
behavior is asserted. The catalog permits rebuild-before-consumption with a
committed typed result, or pre-solver typed `stale_cache` rejection. The initial
review indexed only the cache-attribute/immutability test. However,
`CandidateCOSOperationTests.test_two_beats_use_actual_request_poststate_ledger_and_reference`
inspects the actual second predictor's fresh current, request, ledger and
reference geometry, and asserts that the second beat commits. Geometry and
stage tests also reject stale provenance. Assess that combined evidence against
the catalog outcome and the eventual public operation. Add a targeted test only
for a demonstrated uncovered obligation; do not add a persistent cache or rerun
the full suite merely because the first index was incomplete.

## Two exact-credit checks

**Stale cache.** In [test_grc_v4_lifecycle.py](../../../tests/models/test_grc_v4_lifecycle.py),
`CandidateCOSOperationTests.test_two_beats_use_actual_request_poststate_ledger_and_reference`
wraps the real `CandidateCCurrent` on the second beat. It checks the first
poststate's current, second request ID/duration, prior receipt ledger and reference
geometry; it asserts a committed second result, `(2, 2)` current, clock
`(2, 0.375)` and four newly emitted receipts. The companion
`test_no_cache_input_and_immutable_detached_observations` rejects an injected cache
attribute. `StageCacheTests.test_stale_import_is_rejected_before_any_numerical_rebuild`
in [test_grc_v4_geometry.py](../../../tests/models/test_grc_v4_geometry.py) rejects
stale provenance before a patched numerical solve can run. `_execute` reconstructs
from owned values before consuming them. These establish usable bounded evidence;
the final public result/profile mapping is still required.

**Resource-transform dimensions.** The exact [vector](../../../specs/grc-v4-conformance-vectors.json)
at `/semantic_admission/negative_vectors/1` has source `[u, v]`, target
`[u, v, w]`, coefficients `[1, 0, 0, 1, 0, 0]` and increment `[0, 0]`.
The 3-by-2 matrix has the correct six entries; the increment lacks its third
coordinate. A dimension-valid control keeps those orders and coefficients and
uses `[0, 0, 0]`; that alone establishes no complete target admission claim.

`validate_v4_conformance_contracts` in the
[specification auditor](../../investigations/grc9v4-constitutive-design/scripts/audit_grcv4_post_d10_specifications.py)
checks that exact input's dimension relation and expected `admitted: false`, but
does not obtain the expected diagnostic from a production semantic validator.
This is source inspection, not a fresh audit execution. The live `_affine_resource`
guard already checks both dimensions and graph orders; the test
`CandidateCOSCrossingTests.test_map_shape_conservation_order_and_numeric_wire_domains`
uses a synthetic 2-by-2 transform and expects `invalid_topology_event`.
Thus the demonstrated gap is exact-input/semantic-diagnostic coverage and boundary
integration, not evidence that the receiver accepts malformed dimensions.

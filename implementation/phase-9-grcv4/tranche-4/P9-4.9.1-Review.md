Construction uses either typed fresh `GeometryStageInputs` plus an optional
tuple of complete target references, or `from_config({"initial":
inputs.to_payload(), "targets": [ref.to_payload(), ...]})`. The `targets` array
may be omitted. This is a closed implementation configuration, not a new
scientific payload. `from_state(snapshot, params)` requires serialized resolved
parameters matching the snapshot. Save/load retains the existing C_OS v3
envelope; defaults already belong to the profile's immutable resolved parameters.
An explicit migration changes the active profile/default together; an event
target without a default does not reuse the source profile's request.

The common ABC's legacy annotations name mutable storage classes. Only the
inherited return slots incompatible with those storage classes use `Any` in the
V4 adapter; `state` and `step_v4` retain concrete immutable V4 types. No legacy
storage inheritance, broad override suppression or common-interface edit is
used. The existing approved lazy package export makes
`from pygrc.models import GRCV4` available without loading optional V4 numerical
dependencies during ordinary legacy imports.

## Honest ceilings

- Instance discovery lists exact locally registered C_OS construction/crossing
  profiles, not accepted public conformance. The global accepted registry stays
  empty. Capabilities describe only the executable C_OS methods; there is no
  Candidate A, other realization, GRC9V4 or G2 advertisement.
- `authoritative_current` labels its stage and whether continuity consumed it.
  A read-only reference reconstruction is not the preceding OS corrector.
- The common `abundance` key has **no defined V4 quantity** in the accepted
  sources. It is `null` with `abundance_status=not_defined_by_v4_contract`.
  This is an explicit interim placeholder, not an accepted interface rule,
  zero, resource charge, or inherited
  legacy sink/basin semantics. A numeric abundance contract would need separate
  authority; this leaf does not invent it or claim that diagnostic is implemented.
  The user-proposed P9-4.9.1a now owns the narrow decision. Family/capability
  ownership is the preferred proposal, not accepted authority. The missing rule
  blocks final interface/G2 conformance but does not reopen accepted numerics or
  lifecycle results.
- The initial P9-4.9.3 inventory is not repeated. Its exact 3-by-2 affine
  semantic-negative layer and final 33-case product remain there, followed by
  the single P9-4.8B review. No catalog case is silently waived here.

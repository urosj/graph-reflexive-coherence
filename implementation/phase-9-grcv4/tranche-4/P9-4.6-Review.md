## Implemented contract

`snapshot()` returns a detached, self-contained JSON object. `save()` writes its
canonical JCS bytes; `load()` explicitly decodes that canonical format.
`from_state(snapshot, params=None)` restores this bounded receiver; an optional
resolved-parameter payload is an equality assertion, never an override. This is
an internal API, not the final common-interface facade signature.

The snapshot includes the complete resolved profile, graph/order/orientation,
constant-zero context, typed K4 and reference-Hodge content, exact stable-edge-ID
`W_C_tr` map and identity, scientific current/reset preimages and IDs, persistent
receipt ledger, every commit preimage and ID, and the final lifecycle envelope.
There are no filenames, environment lookups or opaque callables to resolve.
Candidate/OS currents, selectors, Hodge updates, residuals, solver roots and caches
are absent. This layout rejects additional cache/telemetry fields; it does not
silently promote them to authority or claim a general inspection-cache codec.

The release specifies `grcv4-snapshot-v1` and its constituent identity schemas,
but has **no top-level snapshot schema**. The explicit
`implementation_layout_id=pygrc-c-os-snapshot-v1` makes this implementation
choice reviewable. The frozen constituent schemas and wrappers are unchanged.
This does not establish cross-implementation envelope compatibility.

Restoration checks closed shape and I-JSON values; profile/parameter/reference
identities; receipt and commit hashes, grouping and local conventions; graph,
profile, context, reset and charge cross-bindings; and scientific/lifecycle
identities. It then freshly reconstructs and admits **both current and reset** at
reference geometry. A coherent hash does not authorize a singular, wrong-charge,
negative, missing-history or unsupported-profile state. Nothing is exposed until
all reconstruction and readmission passes. No OS pass or writer runs on restore.

`set_state()` accepts a complete typed lifecycle state, revalidates its storage,
and admits a change to **current C only**. Graph, profile, context, reset, Q,
clock/index and ordered ledger must match the live instance. Supplied scientific
and lifecycle IDs must agree with the proposed C. A new C may differ from the
latest commit's target because assignment does not invent a step receipt. Full
restoration is the explicit operation for a different full lifecycle.

`reset()` returns C to the existing reset baseline, preserves graph/profile/Q,
clock and existing ledger, and appends a reset/charge/two-channel receipt delta.
`rebase_reset_baseline()` changes only the reset coordinates to current C and
appends its own delta. Repeated identity resets/rebases still record distinct
operations. Neither operation rebases charge or creates candidate/carrier history.
Both reconstruct and readmit the target before publication.

The V4 reduced reset payload explicitly excludes a baseline clock. This receiver
therefore retains the live clock on reset and rebase, without inventing hidden
clock storage or forcing it to zero. The paper's current-coordinate-only
assignment rule likewise keeps `set_state()` from changing clock/index. Ordinary
positive steps remain the clock writer; construction/full restoration admit an
explicit serialized clock. These are stated receiver conventions, not additions
to the frozen reset schema or claims about legacy reset behavior.

`duplicate()`, `copy.copy()` and `copy.deepcopy()` reconstruct an independent
receiver. Mutable input/output payloads cannot alias current/reset C, graph,
profile, receipts or commit preimages. Immutable observations remain valid after
later operations. Scientific state and retained commit preimages now share one
immutable publication object; an observer cannot see a new state with an old
commit archive. Rejected operations and unexpected exceptions leave both intact.
Saving materializes the bytes before opening the destination; filesystem errors
propagate. No crash-safe or durable-storage transaction is claimed.

## Receipt and import limits

The existing ordinary receipt content and order remain unchanged: step commit,
charge, candidate disposition, carrier disposition. Reset/rebase substitute their
own first receipt. C surfaces are rederived; the absent carrier is
`not_applicable`; no history loss is reported. Resource-transform identity still
means unchanged vertex placement with no event increment, not the nonlinear
ordinary update or administrative C assignment. Actual authority and charge
deltas have their own fields. Reset can legitimately report a nonzero charge
delta within the admitted tolerance; the native witness here reports -2 without
repairing C or changing Q.

Ordinary parents retain the accepted previous-step convention. Administrative
parents name the latest local primary receipt. Administrative operation IDs use
the action and actual source lifecycle digest; no RNG/counter is hidden. Import
accepts only this receiver's four-receipt groups and parent convention, with
complete commit preimages, no duplicate IDs, no foreign graph/profile, no
unreceipted reset change, and declared charge/history semantics. Subdigests and
clock claims referring to the embedded current state must match it; the last
local commit must match the live clock. Consecutive commits must also respect
the actual clock writer: zero-duration ordinary steps keep both fields; positive
steps increment the index once and add at least the smallest binary64 duration;
reset/rebase keep both fields. Arbitrary migration/event lineages reject.

These checks establish content consistency of this bounded serialization, not
proof that externally supplied historical operations occurred. Historical state
hashes are commitments, not reconstructed historical state payloads. Full receipt
ownership, imported lineage semantics and comprehensive replay/failure pressure
remain with P9-4.7a; event/migration products remain with P9-4.7b and Tranche 7.
The local parent convention remains subject to that review. The small positive
continuation witness below does not discharge those larger obligations.

instead of payloads, used the wrong commit prefix, and was asked to encode a
number outside its declared small-dyadic domain. These test-construction errors
were corrected: literal identity tests use the independent oracle within its

An unchanged re-signed positive control prevents a malformed hash wrapper from
making the semantic negative cases vacuously pass. Runtime review also closed the
null-expected-digest bypass and strengthened known-state/charge import bindings.
Further manual pressure after the initial in-process run found that a rehashed
historical commit could claim time 0.5 before a later commit at 0.25. The final
importer now checks consecutive local clock transitions, and the regression
expects that specific rejection after coherent rehashing. The selected run is
repeated after this correction. Current/reset singular restoration also now
asserts `CandidateCStageError(disposition="singular")` explicitly, following a
successful unchanged positive control; it cannot pass on metadata rejection.
No raw debugging logs are retained.

```python
from dataclasses import replace
from tests.models.test_grc_v4_lifecycle import dyadic_fixture, request
from pygrc.models.grc_v4_lifecycle import CandidateCOSOperation

for t in (0, 0.125, 1e308):
    owner = CandidateCOSOperation(replace(dyadic_fixture(), time=t))
    assert owner.step_v4(request(0, "zero")).committed
    assert owner.step_v4(request(5e-324, "positive_minimum")).committed
    restored = owner.duplicate()
    assert restored.snapshot() == owner.snapshot()
    assert (restored.state.step_index, restored.state.time) == (1, t + 5e-324)
```

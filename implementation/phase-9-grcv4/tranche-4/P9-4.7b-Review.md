The bounded `CandidateCOSOperation` accepts an immutable tuple of complete

context or profile preimage is synthesized. Registration is not numerical

reports this local registry; the project conformance support set stays empty.

Same-candidate, nonhistory-to-nonhistory migration preserves current and reset
C, graph, Q and clock while installing the target reference/profile/context
identities and independently readmitting both states. Other unregistered
C/A realization targets reject explicitly. No positive crossing from an
unimplemented A or persistent-carrier source is claimed.

Caller-mapped events evaluate the declared affine map `T C + increment` on
both live and reset resource, in the exact listed vertex orders. Nonnegative
linear coefficients must preserve the unit charge form: each column sums
exactly to one on its binary64 inputs. Neither row normalization nor implicit
vertex reordering repairs a declaration. Coordinate sums are evaluated as
rationals and rounded once per output coordinate; negative or nonfinite
outputs reject. The receipt records the difference between the prescribed
pairwise source and target charge evaluations, and Q changes by that amount.
The bounded accounting domain rejects a delta or Q update that cannot be
represented exactly by its binary64 receipt/state fields. A tiny increment
absorbed in the actual coordinate rounding has actual charge delta zero;
the declared transform identity still distinguishes the request.

Whole target admission includes reset charge/regularity, target reference-map
completeness and fresh Candidate C reconstruction. Current success cannot
substitute for reset success. Candidate history is `rederived`; carrier history
is `not_applicable`; both lack persistent history and information loss. Missing
initializers, invented retained history and unsupported policies reject.
Lifecycle failure records use no step solver disposition; a native target
singularity is a `target_readmission_failure`, with no published delta.

charge values, operation kind and the shared restoration ledger semantics
before publication. Reference, scientific/lifecycle state, commit preimages and

Event identity binds source state/graph, target graph/profile and both map
identities. Operation ID binds receipts/commit but is excluded from event ID;
metadata is nonauthoritative and excluded from the reconstruction archive.

The original closed `pygrc-c-os-snapshot-v1` layout remains readable and is
emitted when sufficient. Layout v2 additionally embeds the complete reference
registry and one request/source/target/reset archive per crossing commit.
Import reconstructs each map, readmits both endpoints, checks exact receipt
preimages and ledger ownership/order, and finally readmits the current snapshot.
No host registry or external file is needed to restore and continue. Recomputed
hashes cannot excuse contradictory archived maps or missing reference content.
These structural/content checks do not authenticate an external historical
trajectory. Lawful unreceipted `set_state()` preserves the distinction.

### Bounded frozen-vector correction investigation

The exact contradiction is between the [specification's structural geometry
contract](../../../specs/grc-v4-spec.md#structural-geometry-and-current-typing),
paper §6, and the committed vector builder's `resolved_params()`. K4 is a
symmetric bilinear form on oriented one-forms. A one-edge graph requires a 1×1
reference preimage, including when that edge is a loop or part of a redundant
incidence representation. The builder unconditionally hashes a 2×2 identity.
The runtime correctly rejects that preimage; resizing it while preserving its
old profile hash, projecting it, or sizing it by vertex count/incidence rank
would violate reference authority.

The accepted side-tool query `D10.2-EC-PARENT-GEOM-K4` resolves to contract
registry row 29, trace
`e1435b36789fa4d37be76d67ff9ec76bd7e8f8680603716b1e836fab21a0340d`.
It reports `source_exact_contract_provenance` and
`indeterminate_requires_review`; no runtime promotion is inferred. The
execution record retains the exact source context and reference.

Rebuilding the frozen vector document reproduces it exactly. Instrumenting its
23 profile-helper calls finds 22 with an edge count other than two: this also
affects the nine-port C_OS/C_PC source and expansion references. Two calls
are used by Candidate A parameter constructors, so the helper's C_OS argument
is not a final-family classification. This count identifies an upstream
construction defect, not 22 independent runtime failures. General GRC9 and
persistent-carrier correction requires its own source/carrier review; the
bounded patch below does not claim to close it.

Dimension correction alone is insufficient. With the original solver's exact
zero residual tolerance, source readmission rejects at inverse retained
identification. For source C=(1,2), the selected constant sector is (1.5,1.5).
Its binary64 deformation is `d=exp(0.25*tanh(1.5))`, and retained identification
is `h=float(d*d)`. The rounded reciprocal has a strictly positive rational
residual `abs(Fraction(h)*Fraction(float(1/Fraction(h)))-1)`, below 2^-52.
Rejecting it under zero tolerance is correct. A tolerance must be declared in
the fixture's complete profile; it cannot be installed as a runtime fallback.

Orientation is a separate representational mismatch. The specification permits
a stable string identity and does not prohibit a named convention. The frozen
source uses `tail_to_head_edge_id_order_v1`; this backend uses the hash of its
complete graph/incidence descriptor. Neither representation can be silently
substituted under an unchanged scientific/reset identity. The corrected
executable fixture explicitly supplies that descriptor and regenerates the
source/reset/event chain.

## Representation boundary

Use tuples for numeric vectors and a V4-owned immutable JSON mapping with
tuple-only backing storage for nested payloads. Do not retain writable arrays,
`dict`/`list`, a mapping proxy's mutable backing dictionary, arbitrary objects,
or cyclic input. Normal Python mutation protection is required; deliberate
`object.__setattr__`, native-memory tampering and hostile concurrent input
mutation are not a security boundary offered by Python value records.
Explicit repeat `__init__`, generated `__setstate__`, and pickle reconstruction
are likewise unsupported mutation/deserialization routes. Untrusted pickle
must never stand in for the future admitted snapshot decoder.

Integral scalars recognized by the standard-library `Integral` ABC are converted
exactly to a Python `int`, checked against the safe-integer range, and only then
converted to binary64. This covers signed/unsigned adapters without fixed-width
absolute-value overflow. Finite floating inputs keep their separate existing
domain, including values outside the safe-integer interval. Booleans are not
numeric coordinates.

Coordinate input is an ordered `Sequence` or a one-dimensional native numeric
buffer, including ordinary arrays and explicitly typed numeric memoryviews.
Mappings, sets, text, raw bytes/bytearray, one-shot iterators/generators, and
untyped iterables reject before iteration. No mapping-value selection, set
sorting, dimension flattening, dtype coercion, or implicit iterator sharing is
performed. Native integer and binary32/binary64 views retain their declared
order, including strides/reversal. Nonnumeric/boolean/structured and nonnative
buffer formats reject; callers must supply an explicitly supported adapter.

Profile, graph, failure and receipt payloads are defensively frozen mappings
at this foundation boundary. They are **not** advertised as admitted profiles,
authenticated receipts, or restored states. Complete profile resolution and
digest recomputation belong to P9-2.2/P9-2.3; receipt/operation admission to
P9-2.4; graph and lifecycle readmission to later owners. These later layers
must validate before exposing an executable model. Construction here checks
basic record shape and local authority-coordinate discrimination, not those
unimplemented contracts. No placeholder digest is generated by production.

Keep current and reset as distinct values; `GRCV4State` stores only its lifecycle
and projects step/time/one `Q_target`/`None`. Step-result receipts are a detached
operation delta, never an alias of the lifecycle ledger. Common event reads
retain `kind`, `step_index`, `payload`, and `source_family`. The result keeps
immutable V4 events internally and returns fresh nominal `GRCEvent` copies on
every `events` read, without transferring writable authority. `_events` is
internal storage for that projection, not an extra serialized result field.

```bash
.venv/bin/python -m unittest discover -s tests/models -p test_grc_v4_state.py -v
.venv/bin/python -m unittest discover -s tests/core -v
.venv/bin/ruff check src/pygrc/models/grc_v4_state.py tests/models/test_grc_v4_state.py
```

## Implemented boundary

`grc_v4_profile` owns frozen typed parameter records, complete-profile and
candidate-discriminated template identities. Every supplied parameter remains
in the projected payload; there is no ambient configuration, callable-name
lookup, default coefficient, or mutable map alias. Exact duplicated
common/candidate/realization fields are cross-checked, including the C map's
versioned digest. CI+PC retains `rho_inst = 1` and composition gain two.

`resolve_profile` returns a consistent declaration, not a live admitted model.
Algorithm IDs (including solver, geometry, charge and lifecycle identifiers)
remain declarations until their executable owners resolve them; this leaf
does not infer an algorithm from a label. `list_supported_profiles()` is empty
and executable lookup fails explicitly. The ten synthetic examples exercise
typed shape resolution, not certified CI/RG2b/PC domains or complete dynamics.

`validate_profile_references` independently recomputes the supplied K4/Hodge
preimages and checks Hodge/C-map coverage against the supplied stable live-edge
roster. For C it also requires exact reference Hodge/W_C_tr weights by stable
edge ID, as required by D11-C's distinct typed reference constructors.
P9-3.1 owns admission of that roster's actual graph and geometry domain;
this function is neither graph validation nor a persistent reference registry.
No Hodge-to-mobility transfer, edge-order substitution, or target repair occurs.

The codec provides detached primitive JSON decoding, closed-schema validation
and named-preimage hashing as separate operations. Hashing an event, receipt,
state or GRC9 payload does not execute or admit its scientific semantics. The
remaining operation-specific semantic validator/strict-request split belongs
to P9-2.3 and later lifecycle owners.

H1: record equality compares JCS bytes, preserving boolean/number distinctions;
only the prefixed SHA-256 identities are scientific identities. Python's
process-local `hash()` is not a portable identity. H2: the P9-2.1 map retains its
tuple-only immutable storage but now exposes direct item traversal, eliminating
repeated linear lookups during refreezing, equality and codec projection.
Scale checks at 16/256/4096 keys prohibit any per-key lookup on those paths.

## Independent audit corrections

The [retained audit inputs](../evidence/P9-2.2/independent-audit-inputs/inputs.json)
preserve the three supplied files and the original uncommitted code/test/review
bytes needed to inspect their subject. All six supplied source/test bindings
matched. The two additional evidence artifacts named by the report were not
supplied; they are not claimed as retained. The audit's missing package and
G1 evidence was an upload limitation, not evidence that those checks failed.

- R1: schema-admitted integral floats now become Python `int` in every
  `iteration_limit` owner and the CI+PC integer constant `rho_inst`, after
  validation, through both direct and payload constructors. Tests cover nested
  records, `operator.index`, domain rejection and unchanged canonical IDs.
  Nonintegral coefficients retain their original meaning; no truncation occurs.
- R2: strict `decode_json` remains a configuration decoder, not the inverse of
  JCS over all admitted binary64 values. The separate `decode_canonical_json`
  accepts only the exact canonical image of that existing value domain.
  Integer-shaped tokens beyond the safe-integer range explicitly represent
  binary64 on this route; exact re-encoding must reproduce every input byte.
  Thus canonical `9007199254740992` works, while `9007199254740993` rejects.
  This does not admit arbitrary-precision native integers or change the strict
  configuration policy. Count/index fields still require their safe schema.
  `GRCV4Profile.from_canonical_bytes` additionally validates the closed envelope,
  resolved parameters and complete identity. It restores a declaration only,
  not an admitted snapshot or operation. Large magnitudes, subnormals, signs,
  exponent boundaries, rounding, forged identities and installed restoration
  have regressions. Frozen schema, vectors and canonical bytes are unchanged.
- F1: the local reference checker enforces
  `E_H(W_C_tr) = H1_form,ref = Diag(W_C_tr)` across all five C shapes.
  Rehashing conflicting values or substituting `eta_C * W_C_tr` now fails.
  Stable-ID ordering, immutability and the separate mobility authority remain
  intact. The bounded forensic trace and exact accepted
  [D11-C construction](../../investigations/grc9v4-constitutive-design/decisions/D11CCandidateBaselineTransportAndMobilityResolution.md#typed-construction)
  are bound in the correction run. This does not implement graph/SPD or trial
  geometry admission, which stay with P9-3.1/P9-4.1 and their later owners.

## Reproduction

From the repository root, after installing `.[v4]` into `.venv`:

```bash
.venv/bin/python -m unittest tests.models.test_grc_v4_state tests.models.test_grc_v4_codec.CodecTests tests.models.test_grc_v4_profile -v
.venv/bin/python -m unittest discover -s tests/core -v
.venv/bin/python implementation/phase-9-grcv4/verification/audit_phase9_implementation.py --boundary-only
```

The retained run gives the exact static-check and offline-distribution commands.
For a fresh machine, fetch the recorded dependency wheel versions appropriate
to its interpreter/platform into a repository-relative wheelhouse, then set
`GRCV4_PACKAGE_TESTS=1` and `GRCV4_WHEELHOUSE` to that directory. Another platform
is a new reproduction run, not the original accepted environment. Build tools
are test dependencies, not extra runtime imports or new baseline dependencies.

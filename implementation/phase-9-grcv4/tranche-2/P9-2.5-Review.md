## What executes, and what does not

`run_negative` executes the actual `negative_duration_result` once. Independent
expected values are calculated before invocation; the harness owns and captures
the input, scientific state, ordered ledger and reset baseline before/after.
Its outcome labels describe the negative-input admission branch it invokes;
they are not copied from the returned receipt. No solver is called. This
demonstrates prefix rejection with captured value preservation, **not** rollback
of a mutable numerical model or observation of a twelve-stage solver journal.

The concrete three-node/two-edge C_OS declaration carries all parameter,
profile, graph, K4, reference-Hodge, context and reset preimages. K4 is
nonidentity SPD and live resource differs from reset resource. Digests are
recomputed independently; no unrelated nine-edge profile label is reused.
The port-shaped graph payload is data, not GRC9 specialization admission.
Reference coverage and identities are checked before invocation; the fixture
explicitly remains `declared_not_runtime_admitted`.

Caller-provided operations always produce `harness_mutation_control`, even
when returning an imported matching result. `assess_negative`, stored reports
and integrity checks alone never certify that an operation executed. Nonnegative
requests cannot enter this prefix adapter. Positive/zero full-step execution,
complete context/graph/domain admission and actual numerical failure injection
remain with their authorized consumers.

## Independence and comparisons

The reference module imports neither production code, NumPy solvers nor the
vector generator. It uses the frozen vector bundle only as checked data.
The independent identity writer deliberately supports printable ASCII and small
exact dyadics only: fractional magnitude is below `2**16` with at most six
fractional bits; integral values span the safe-integer range. Out-of-domain
identity input raises an oracle-domain error before invocation, with no
production-code fallback or change to the scientific binary64 domain.
Published canonical bytes anchor this restricted writer. Evidence JSON has its
own deterministic encoding and is never substituted for scientific JCS.
Exact request JCS bytes are retained separately, including numeric/Unicode
cases outside the identity oracle's restricted envelope.

All current failure/state/ledger/request/receipt comparisons are exact. Numeric
comparison helpers separately require either exact binary64 values or explicit
absolute/relative tolerances and field scope. Fractions prevent overflow-driven
`inf <= inf` false positives and comparison-boundary enlargement. Tolerance does
not apply to identities, order, counts, booleans or atomicity. Environment binds
Python, binary64 characteristics, architecture and dependency versions. This
adapter uses no NumPy/BLAS solver, random seed or thread-sensitive computation.

The independent charge reference rounds each balanced-tree sum to binary64;
it never repairs resource. The clock control uses a **declared fixture
convention** (one index increment and one RN-even time addition for positive
duration; identity for zero). It is not new frozen normative authority.
The future step owner must bind its accepted clock convention. Tiny positive
duration may leave represented time unchanged; no strict time-increase test
is imposed.

No archive or external evidence service is required. `inspect_run` validates
stored artifact linkage and assessment without invoking production execution;

integrity, not independent authentication of execution or user acceptance.

side tool's ignored generated directory; no machine paths are published.

to the exact default fixture and default adapter. A non-default request or
callback control cannot borrow its command. Other assessments and malformed
capture diagnostics remain inspection/test evidence; they do not gain a
default-CLI reproduction recipe. The fresh repository CLI is the supported
execution route, not a claim of arbitrary long-lived-interpreter attestation.

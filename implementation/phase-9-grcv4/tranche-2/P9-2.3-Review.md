## Implemented pressure and limits

Malformed UTF-8/JSON and wrong input shapes raise before semantic admission.
Shape-valid negative duration yields the exact typed failure receipt; no
model, mutable prestate, cache or ledger is passed to that pure prefix. Positive
and zero durations yield strict request records; zero duration does not bypass
later state admission or certify an identity transition. No post-solve failure
or complete atomic runtime vector is claimed by this prefix.

Carry the audits' safe-integer/native-binary64 distinction, exact canonical
reconstruction, boolean/number separation, direct/factory consistency, nested
copy isolation and strict reference/receipt identities. Harness fault payloads
are not production requests, callbacks or identity fields. Snapshot/pickle
restoration is not a request-decoding route. Verify malformed input precedence,
rehashed non-atomic failure evidence, round-trip edge cases and forged records.

Two additional counterexamples were confirmed against the committed P9-2.2
codec before correction:

- Identity patterns ending in `$` admitted a final newline under the Python
  regex implementation. The V4 validator now uses full-string matching for
  the pinned identity grammars. Source, target and receipt references may not
  be repaired or trimmed. Frozen schema bytes and digest preimages do not change.
- A nonzero duration token such as `1e-4000` decoded to zero. Both numeric
  decoding routes now reject nonzero-to-zero binary64 underflow, rather than
  changing the duration branch. Literal zero and representable subnormals are
  retained; ordinary binary64 rounding is not replaced with decimal arithmetic.

The public request decoder selects only the generic input/migration schemas;
it does not reinterpret a strict request, snapshot or harness record as wire
input. `V4DecodeShapeError` is a wire error with a schema-error cause. Missing
dependencies/assets remain environmental exceptions, not scientific failures.
Migration declarations enforce both typed history channels and exact reference
grammar, but neither authenticate a live source nor resolve target support.

`admit_step_request` accepts exactly a `GRCV4StepRequestInput`, detaches and
revalidates it, then returns either a strict `GRCV4StepRequest` or a content-checked
`FailureReceipt` for negative duration. Wrong Python types and corrupted
records raise. Source-state identity is a mandatory, grammar-checked argument
from the future lifecycle owner; a digest alone is not state authentication.
Failure receipt constructors recheck their identity and reject unequal
source/poststate digests even when the caller rehashes that inconsistency.
They cannot contain commit IDs or persistent-ledger changes. No solver status
is manufactured. P9-2.4 still owns full result/disposition/ledger composition.

### Consumer checks assigned, not prematurely implemented

The existing plan and checklist now explicitly require:

- P9-2.4: negative-duration result has rejected operation disposition,
  `solver_disposition=None`, no commit ID and no persistent append. Bind receipt
  operation/stage/code/source/poststate to actual execution, not just content.
  Preserve `valid_root` if a later charge rejection follows a successful solve.
- P9-2.5 and the real step/lifecycle owners: retain the exact request separately
  from its receipt. Different negative requests can have identical receipts;
  neither idempotency nor replay permission follows. Reject foreign/rehashed
  evidence and grammar-valid wrong source identities using actual state.
  Compare full scientific and lifecycle payloads as well as digests, and test
  emitted receipt delta separately from persistent ledger contents.
- P9-2.6/P9-4.4/P9-4.5/P9-4.7a: zero, subnormal and extreme finite duration do
  not bypass full graph/profile/context/domain admission. Current no-facade
  assertions are leaf-stage checks, not a permanent prohibition on the later
  authorized facade. Tranche 7 owns real source/history/map/target admission;
  decoding a migration declaration cannot substitute for it.

These are tests for existing downstream responsibilities, not new gates,
scientific debt, runtime-support claims or authorization to start P9-2.4.

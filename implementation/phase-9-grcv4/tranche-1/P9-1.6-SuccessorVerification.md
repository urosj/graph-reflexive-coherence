filtering Git output, removing assertions, or rewriting historical boundaries.

checkout is removed after its checks. Full history and the declared local

environment so the historical auditor's interpreter-identity check also runs

specification, test, or authority path is hidden or excluded from an audit.

## Current-tree policy and fail-closed behavior

The [successor boundary](../verification/Phase9VerificationBoundary.json)
binds the opening, exact release/checkpoint, thirteen permitted files, and
the candidate's content hashes. The policy digest excludes only its own
digest field. The execution record binds that digest; it is not included in
the policy's file hashes to avoid a circular reference. Its authority and
scope fields are checked separately and cannot grant runtime permission.

All pre-existing Phase 9 review evidence, investigation source/accepted tool
records, specifications, production source, tests, and dependency metadata
remain unchanged. Untracked source/test additions are checked even if ignored
by Git. Existing tool-generated/cache outputs are not treated as scientific
or runtime authority. Five named editable-install `src/pygrc.egg-info` metadata
files are also generated environment outputs; arbitrary files in that directory
are not exempt, and `pyproject.toml` remains protected. Unrelated work outside the declared protected scope is
not subjected to a new repository-wide freeze.

Dispatch uses the opening's presence or its recorded Git ancestry only to
select a verifier. The selected verifier validates actual hashes, statuses,
scope and ancestor/merge facts. Deleting the marker cannot select the older
route. A green string cannot override a failing process exit code. The normal
summary uses `verified_implementation_planning`, not an invented acceptance.

This version supports only the present planning state. A future implementation
state fails closed until the explicitly reviewed P9-G1 successor supplies its
own policy and exact V4 additions/additive integration scope. Neither a flag
nor the old acceptance permits `src/`, `tests/`, or dependency changes.
Later P9-1.7/P9-1.8 work extends this candidate with its own bounded records;
new files are not authorized merely by being under a V4 directory. Historical
specification envelopes and release-bound bytes will remain untouched.

Hashes here are local integrity/provenance checks, not a signature or a claim
that an attacker who rewrites the verifier itself can be detected by that
same verifier. Human review and subsequent gate acceptance remain separate.

## Sources and forensic method

The [generic spec](../../../specs/grc-v4-spec.md),
[V4 interface extension](../../../specs/grc-common-interface-v4-ext.md), and
[GRC9V4 spec](../../../specs/grc-9-v4-spec.md) define the implementation
contracts. The [paper](../../investigations/grc9v4-constitutive-design/drafts/2026-09-GRC-V4.md)
supplies the mathematical interpretation, and the
[proposal](../../investigations/grc9v4-constitutive-design/drafts/GRCV4-proposal.md)
supplies its fuller provenance crosswalk. Accepted investigation records
preserve the claim classes and authority boundaries. The tool is the
provenance spine, not a replacement source.

The auditor loads the accepted successor context, enumerates identifiers,
then queries `reconstruction_path`, `contract_provenance`, and
`debt_lifecycle`. It retains exact source payload fields, classifications,
source references, and trace digests. Current claims are joined to contracts
only through their source-recorded `accepted_claim_ids`; the additional
`claim_boundary` planning consumer does not create a support edge.
Schema definitions and exact spec/paper headings are checked against source
files, and all planning iteration IDs must exist in the checklist.

Direct JSON is used for the literal verification registry where there is no
dedicated public obligation query, and for the provenance-only locator
`D10_2_CL_N_001`. Registry payloads with typed forward witnesses must agree
exactly with those witnesses. The locator must still raise `KeyError` through
claim reconstruction; its presence as text does not admit it as a graph claim.

Backward reconstruction traverses substantial predecessor history. Its
stored edge list is explicitly projected to edges incident to the queried
claim; the full edge set has a count and SHA-256 binding and the complete
API trace is reproducible. Direct contract/debt queries retain all edge
locators. Nested predecessor lineage is retained in the original source and
hash-bound rather than duplicated; top-level debt claim links and all
dispositions remain exact. These are evidence projections, not complete
copies of the API traces.

Every artifact binds the source files, accepted release, and forensic context.
The auditor reconstructs all three artifacts without writing any source,
graph, runtime state, or accepted record.

The register provides the dependency DAG. Codec primitives sit below profile
and immutable state; geometry/transport and candidate providers feed realization
and provisional step evaluation; lifecycle owns the authoritative commit.
The facade supplies the public interface. Generic modules never import
GRC9V4 mechanics. Dependencies are interface requirements, not eager imports:
an unavailable Candidate A, PC, or RG2b implementation cannot prevent importing
or testing C_OS. No module advertises an inferred candidate×realization product.

There is exactly one authoritative commit/rollback owner. The step evaluator
produces one provisional resource update and post-state checks; lifecycle
commits the complete accepted tuple once. Migrations/events use the same
readmission/commit boundary, not `set_state()` shortcuts. Scientific state,
reset baseline, persistent receipt ledger, and operation receipt delta keep
their specified distinct roles.

Public methods retain the [interface extension's](../../../specs/grc-common-interface-v4-ext.md)
calling contracts: `from_config`, `from_state`, `load`, state/parameter
access, `step`, `run`, `reset`, `rebase_reset_baseline`, `snapshot`,
`save`, and observables/capabilities. Add `step_v4`, `run_v4`,
`migrate_profile`, `apply_topology_event`, exact profile lookup, and combined
model-identity discovery. Zero-argument stepping delegates only through a
serialized immutable default request; no hidden queue or environment input.

### Integration boundaries found in existing code

1. **P9-INTEGRATION-001 — nominal typing versus immutable records.**
   The frozen [GRCModel interface](../../../src/pygrc/core/interfaces.py)
   annotates state/results with mutable legacy dataclasses.
   [Those dataclasses](../../../src/pygrc/core/types.py) cannot be storage
   superclasses for the standalone immutable V4 records required by the spec.
   Recommend V4-local structural protocols and defensive immutable values,
   with narrowly documented `override` typing exceptions only where the
   unchanged nominal annotation forces one. Accept broad common input types
   and validate V4 compatibility; do not narrow inherited input domains silently.
   Never cast an unrelated record into a legacy runtime instance, inherit
   mutable storage, or suppress whole-module typing. P9-2.1/P9-2.6 must test
   the common method/field contract, immutability, and exact exception sites.

2. **P9-INTEGRATION-002 — codec and capability separation.**
   The [legacy serializer](../../../src/pygrc/core/serialization.py) uses
   sorted Python JSON with ASCII escapes, not the full V4 JCS contract.
   Keep it unchanged. V4's own codec must enforce UTF-16 key ordering,
   finite ECMAScript binary64 representation, the forbidden-number boundaries,
   duplicate-key rejection, and the published identity preimages.
   The [legacy capability test](../../../tests/core/test_capabilities.py)
   intentionally fixes four older families. Keep that registry/test unchanged;
   provide V4-owned exact-profile/capability discovery through the new facade.

3. **P9-REVIEW-001 — acknowledged, not upgraded.**
   The 152 D10.2 contract support dispositions remain
   `indeterminate_requires_review`; D11's bounded dispositions remain exact.
   This review acknowledges that limit without claiming missing accepted
   specification authority or manufacturing stronger graph edges. P9-1.6
   should preserve a visible diagnostic, not “fix” the scientific semantics.

The integration/type observations are engineering work items, not new
investigation debt or authorization to amend accepted equations.

diffs; filenames in this review do not themselves grant permission.

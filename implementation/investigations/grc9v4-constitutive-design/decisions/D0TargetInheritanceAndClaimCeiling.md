
This universe is exhaustive only over the named pre-D1 families. It is not
exhaustive over all possible GRC9V4 architectures. Candidate-family names are
investigation classifications, not mutually exclusive ontological truths.
Reclassification is allowed when the causal architecture is unchanged;
material hybridization or a changed state, accounting, transport, write/read,

`source-backed` does not require a paper to name the candidate. It includes a
transparent constitutive derivation from frozen core requirements when the
steps and assumptions are visible, core vetoes are preserved, and the result
remains labeled a candidate completion.

architecture. Current temporalization remains a separate D6 axis.

the first D1 candidate result. It must be source-backed and causally distinct.

than a post-result addition to the current set.

source missed by D0 reopens D0. A genuinely new post-D0 theory result enters a
named theory-derivation route and supersedes affected gate records; neither is

## Reduction Contract

For each admitted candidate `a`, D1 must construct:

```text
i_a  : X_V3 -> X_V4_a_disabled
pi_a : X_V4_a_disabled -> X_V3
```

The eventual completed transition must satisfy:

```text
pi_a(F_V4_a_disabled(i_a(x))) = F_V3(x)
```

D0 freezes the reference and comparison rules, not the candidate maps or a
transition witness.

| Surface | D0 equivalence requirement |
| --- | --- |
| transition | projected exact by default; any numerical tolerance is declared and frozen before D9 |
| snapshot | projected semantic equality; raw byte equality is not required |
| observables | projected exact for names, types, and categorical values; numeric exact by default |
| event/lifecycle | projected exact for event identity/order/payload, topology, registries, step/time, RNG, and reset baseline |

Added disabled state must be deterministic, neutral, free of hidden budget/RNG
effects, and serialized if independently causal. Representation-only cache
normalization does not define scientific identity.

One-step coincidence is insufficient. The embedded V3 state space must be an
invariant subspace of disabled V4:

```text
F_V4_a_disabled(i_a(X_V3)) is contained in i_a(X_V3)
```

Disabled added state must remain canonical and causally inert over repeated
steps. It cannot accumulate hidden history that affects later re-enabling.
Re-enabling starts from canonical neutral added state unless a separate,
non-parity migration profile is later specified.

The external complete-step clock, step index, and synchronous time semantics
must match V3. Internal no-op stages, iterations, or implicit solves are not
required to match V3 staging. Projection may hide only neutral added state or
representation caches, never a field affecting V3 observables, events, budget,
topology, or future evolution.

D1 may establish state-space compatibility and reduction obligations. It may
not claim completed transition commutation before D7 closes the transition and
D9 executes the witness.

## Topology Scope

D0 separates two scopes.

```text
design/verification envelope:
  fixed-topology, event-free smooth strata by default

normative runtime capability scope:
  full GRC9V3-capability successor
```

The fixed-topology envelope allows local ontology, operator, and loop analysis.
At a topology event, smooth analysis stops and records an event boundary. Node
lineage does not transport retained state automatically.

The eventual V4 profile is not silently reduced to fixed topology. It must
define retained-representation transport/reconfiguration, resource accounting,
parent/child or interspace identity, lifecycle ordering, and reset/release or
termination behavior across inherited topology-changing mechanics. This is a
hard `must_close_before_D10` debt.

Every later result must carry one of:

```text
fixed_verification_envelope
fixed_topology_normative_subprofile
full_topology_capable_V4
```

Fixed-envelope success cannot be promoted to event/topology semantics.

## Vetoes And Preferences

Hard vetoes include authority separation, typed retention/read/write roles, the
Read-Back passive null, oriented edge-cochain output, separation of `J0`, `j`,
and `J_C`, complete causal-state serialization, no observer-projector relabel,
candidate-specific V3 reduction, budget integrity, topology-event closure, and
disabled-profile legacy semantics.

Selection preferences include minimal independent state, source-derived
representations where constitutively complete, explicit ownership, small lawful
extension surfaces, analytical identifiability, simple lifecycle behavior, and
reuse of legacy mechanics without semantic relabeling. A preference cannot
override a veto or reject the only architecture satisfying the target.

Vetoes are typed as claim-scope, candidate-fatal-for-target, candidate-fatal,
gate-fatal, or specification-blocking. Missing joint structural theory blocks
the joint structural-alpha claim; it does not automatically reject a candidate
that uses a conditional `C` structural operator and a temporal retained state.
